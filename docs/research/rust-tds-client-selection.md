# Rust SQL Server/TDS client selection

**Ticket:** `rfs-7nki`  
**Decision scope:** the smallest in-process Rust route for the already-charted *Prove the SQL Server TDS transport boundary* throwaway prototype. This note evaluates client libraries, not a SQL Server adapter implementation.

## Decision

Use Praxiom Labs' `mssql-client` **0.20.2** as the primary prototype client, behind a tiny ResourceFS-owned transport seam. It is the smallest candidate whose public surface already has all of the difficult lifecycle pieces that `MutationAdapter` needs: typed SQL parameters and values, incremental row/LOB streaming, explicit type-state transactions, query timeout, cancellation, and typed error categories ([`Client` API](https://docs.rs/mssql-client/latest/mssql_client/struct.Client.html), [`RowStream`](https://docs.rs/mssql-client/latest/mssql_client/struct.RowStream.html), [`Error`](https://docs.rs/mssql-client/latest/mssql_client/enum.Error.html), [`mssql-types`](https://docs.rs/mssql-types/latest/mssql_types/)). It is still pre-1.0 and its support document identifies a single-maintainer, best-effort maintenance model, so this is a **conditional selection**, not an unconditional production approval ([stability policy](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/STABILITY.md), [project status](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/README.md)).

The prototype should pin the exact crate versions and make the following gates hard failures: type-preserving row round trips; canonical NULL, temporal, GUID, binary, and decimal handling; bounded row and MAX-value streaming; cancellation and timeout that leave a connection reusable or retire it; rollback on every failure; TLS hostname/CA rejection; each required authentication mode; SQL Server 2017/2019/2022 plus at least one legacy/Azure target; and stale-row conflict behavior. The driver does not create ResourceFS JSON, keys, Version Tags, grants, catalog policy, or mutation receipts; the adapter still owns those semantics.

Keep two alternatives explicit:

* `odbc-api` **29.0.0** is the fallback when Microsoft ODBC Driver deployment and a blocking actor are acceptable. It has strong catalog, parameter, transaction, diagnostics, and query-timeout coverage, but its async polling is driver-dependent and its safe public surface does not expose query cancellation; it therefore needs a stronger actor/connection-retirement proof than `mssql-client` ([guide](https://docs.rs/odbc-api/latest/odbc_api/guide/index.html), [`Connection`](https://docs.rs/odbc-api/latest/odbc_api/struct.Connection.html), [`Statement`](https://docs.rs/odbc-api/latest/odbc_api/handles/struct.Statement.html), [source](https://raw.githubusercontent.com/pacman82/odbc-api/main/odbc-api/src/handles/statement.rs)).
* Microsoft's `mssql-tds` is the best long-term protocol-alignment watch item and has an excellent low-level cancellation/transaction surface, but it is currently a git-only, `0.1.0`, actively changing workspace crate. Microsoft has not published it to crates.io; the open publication issue says git dependency is currently the only consumption route ([workspace README](https://github.com/microsoft/mssql-rs), [`mssql-tds/Cargo.toml`](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/Cargo.toml), [publication issue #159](https://github.com/microsoft/mssql-rs/issues/159)). Do not make it the production dependency for this prototype. Its temporary `mssql-tds-preview` package is explicitly an unmodified fork that will be yanked when the official crate lands ([preview package](https://docs.rs/crate/mssql-tds-preview/latest)).

`sqlcmd` remains a **pinned, read-only oracle only**. It may corroborate catalog and a small JSON projection, but its textual substitution and stdout protocol are not a safe typed mutation boundary ([Microsoft `sqlcmd` utility](https://learn.microsoft.com/en-us/sql/tools/sqlcmd/sqlcmd-utility?view=sql-server-ver17), [sqlcmd commands](https://learn.microsoft.com/en-us/sql/tools/sqlcmd/sqlcmd-commands?view=sql-server-ver17), [FOR JSON](https://learn.microsoft.com/en-us/sql/relational-databases/json/format-query-results-as-json-with-for-json-sql-server?view=sql-server-ver17)).

## What the ResourceFS seam requires

The current core passes an `OperationGuard` into source reads and discovery; the guard can be cancelled, awaited, and transitioned into a commit phase ([`OperationGuard`](../../crates/resourcefs-core/src/session.rs#L191-L275), [`SourceAdapter`](../../crates/resourcefs-core/src/source.rs#L5-L20), [`DiscoveryAdapter`](../../crates/resourcefs-core/src/discovery.rs#L451-L467)). Mutation is a fixed operation model: resolve, load, then commit `Create`, `Replace(expected VersionTag)`, `Delete(expected VersionTag)`, or same-source `Move`, all with the guard ([`MutationAdapter`](../../crates/resourcefs-core/src/mutation.rs#L1136-L1177)). The core requires source-specific compare-before-write, serialization per canonical resource, and unchanged state when validation or commit fails ([`DESIGN.md` mutation rules](../../DESIGN.md#mutation-versioning-and-concurrency)).

The SQL route must therefore provide, or allow the adapter to prove:

1. **Typed, lossless cells and parameters.** Keys, NULLs, binary, JSON text, decimal/temporal values, and concurrency tokens must be bound as values, never interpolated into SQL. SQL Server treats parameters as literals, while identifiers require validated component-wise quoting such as `QUOTENAME` ([parameters](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/configuring-parameters-and-parameter-data-types), [secure dynamic SQL](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql/writing-secure-dynamic-sql?view=sql-server-ver17), [QUOTENAME](https://learn.microsoft.com/en-us/sql/t-sql/functions/quotename-transact-sql?view=sql-server-ver17)).
2. **Bounded reads and backpressure.** A row list/search must impose ResourceFS ceilings and deterministic PK ordering. SQL Server does not guarantee row order without `ORDER BY`; `OFFSET`/`FETCH` require ordering ([`ORDER BY`](https://learn.microsoft.com/en-us/sql/t-sql/queries/select-order-by-clause-transact-sql?view=sql-server-ver17)). Driver streaming is useful but does not itself impose ResourceFS byte/row limits.
3. **One-connection explicit transactions.** Validation, current-state comparison, DML, generated-value retrieval, and commit must remain on one connection and one short transaction. SQL Server's transaction unit is explicit `BEGIN`/`COMMIT`/`ROLLBACK` ([transactions](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/transactions-transact-sql?view=sql-server-ver17), [BEGIN TRANSACTION](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/begin-transaction-transact-sql?view=sql-server-ver17)).
4. **Two concurrency contracts.** Use PK plus old `rowversion` when present; otherwise compare every authoritative, nullable-safe original value. `rowversion` is an 8-byte counter, not a content tag, and it can change even for an update that writes the same value ([`rowversion`](https://learn.microsoft.com/en-us/sql/t-sql/data-types/rowversion-transact-sql?view=sql-server-ver17), [optimistic concurrency](https://learn.microsoft.com/en-us/sql/connect/ado-net/optimistic-concurrency?view=sql-server-ver17)). ResourceFS continues to expose `sha256:` over canonical JSON bytes ([`VersionTag`](../../crates/resourcefs-core/src/version.rs#L5-L50)).
5. **Cancellation that reaches the server or retires the connection.** An `OperationGuard` cancellation must not merely stop awaiting while a worker keeps mutating. A successful prototype must show server attention/rollback or prove that the connection is discarded and no later pool borrower can observe an open batch/transaction.
6. **Explicit TLS and authentication policy.** Certificate verification must be on by default; `TrustServerCertificate`-style bypass is development-only. SQL login, integrated/Kerberos, and Entra/Azure token paths are distinct tests, not interchangeable claims. Microsoft documents authentication, encryption, and certificate validation separately ([authentication](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql/authentication-sql-server?view=sql-server-ver17), [encryption/certificate validation](https://learn.microsoft.com/en-us/sql/connect/ado-net/encryption-and-certificate-validation?view=sql-server-ver17)).
7. **Source-owned projection.** Catalog metadata must use named columns from `sys.schemas`, `sys.tables`, `sys.columns`, primary-key constraints, and index order; catalog visibility is permission-dependent ([catalog views](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/catalog-views-transact-sql?view=sql-server-ver17), [`sys.columns`](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-columns-transact-sql?view=sql-server-ver17), [`sys.key_constraints`](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-key-constraints-transact-sql?view=sql-server-ver17), [`sys.index_columns`](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-index-columns-transact-sql?view=sql-server-ver17), [metadata visibility](https://learn.microsoft.com/en-us/sql/relational-databases/security/metadata-visibility-configuration?view=sql-server-ver17)). Neither a driver nor `FOR JSON` decides the ResourceFS canonical column order, supported SQL type subset, key encoding, or Version Tag.

## Candidate inventory and disposition

| Route | What it is | Disposition for the prototype |
|---|---|---|
| **Praxiom `mssql-client` 0.20.2** | Pure-Rust, Tokio-native high-level client over TDS 7.3–8.0; streaming, transactions, cancellation, TLS, auth, pooling | **Primary, conditional.** Best seam fit; pre-1.0 and documented type/platform gaps must be gated. |
| **Tiberius 0.12.3** | Established native async TDS client; runtime-flexible and broad type support | **Fallback.** Good read transport, but transaction/timeout/cancellation are not first-class APIs. |
| **Microsoft `mssql-tds` 0.1.0** | Microsoft-owned low-level async TDS foundation | **Watch, not dependency.** Strong API shape; git-only and unstable. |
| **`mssql-tds-preview` 0.1.0-preview.9** | Temporary crates.io mirror of Microsoft's crate | **Do not adopt.** Its own documentation says it will be yanked. |
| **`odbc-api` 29.0.0 + Microsoft ODBC Driver** | MIT Rust ODBC abstraction over a native driver manager/driver | **Fallback/compatibility path.** Strong metadata and transactions; external deployment, blocking behavior, and no safe cancel method. |
| **`sqlx-mssql-odbc` 0.1.8** | Young SQLx facade over ODBC with a dedicated blocking actor | **Do not choose over direct `odbc-api`.** It adds a useful SQLx API but its source does not pass ODBC query timeouts or cancellation through the actor. |
| **SQLx mainline** | Async pure-Rust SQL toolkit | **Falsified.** Its official README says MSSQL was removed before 0.7 pending a rewrite; current drivers are PostgreSQL, MySQL/MariaDB, and SQLite ([README](https://github.com/launchbadge/sqlx), [Cargo manifest](https://raw.githubusercontent.com/launchbadge/sqlx/main/Cargo.toml)). |
| **`ms-tds` 0.1.1** | Another pure-Rust TDS client | **Falsified.** Its own docs call it pre-alpha and state row/COLMETADATA decoding is not implemented ([docs](https://docs.rs/ms-tds/latest/ms_tds/index.html)). |
| **Legacy `odbc` 0.17** | Older Rust ODBC wrapper | **Falsified.** Its repository carries the “Unsupported” status and says work has ceased ([README](https://github.com/Koka/odbc-rs)). |
| **`tokio-odbc`** | Proposed Tokio ODBC wrapper | **Not a current route.** No current docs.rs crate exists at the expected package URL ([docs.rs lookup](https://docs.rs/tokio-odbc/latest/tokio_odbc/)); use `odbc-api` with an explicit actor instead. |
| **`tds-protocol` 0.20.2** | Low-level protocol primitives extracted from Praxiom's stack | **Not a client.** Its docs say it is IO/runtime agnostic and primarily used internally by `mssql-client` ([crate page](https://docs.rs/crate/tds-protocol/latest)). |

The inventory treats wrappers and protocol components as separate routes only where their source changes the operational contract. Small ORM/DSL integrations are not independent transports: they eventually select one of TDS or ODBC and would add a second mapping layer to a source that already needs dynamic catalog-driven SQL.

## Detailed comparison

### 1. Praxiom `mssql-client`: primary

**Typed values and parameters.** `mssql-client` exposes `Client::query`, `execute`, named parameter variants, and the `mssql-types` `ToSql`/`FromSql` traits. The type crate provides SQL/Rust mappings for integer, floating, bit, text, binary, date/time, UUID, decimal, and optional JSON types, plus explicit typed wrappers for precision/scale and typed NULLs ([client docs](https://docs.rs/mssql-client/latest/mssql_client/struct.Client.html), [type crate](https://docs.rs/mssql-types/latest/mssql_types/)). This is appropriate for metadata-driven SQL because the adapter can generate only validated identifiers and bind all cell values. The documented hard boundary is important: the driver rejects or exposes as raw data several types including spatial, `hierarchyid`, CLR UDTs, and decimal/numeric values beyond roughly 28–29 significant digits; SQL Server itself allows decimal precision up to 38 ([limitations](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/LIMITATIONS.md), [SQL Server decimal](https://learn.microsoft.com/en-us/sql/t-sql/data-types/decimal-and-numeric-transact-sql?view=sql-server-ver17)). Phase one must fail closed for those types, not stringify them silently.

**Streaming and bounds.** `query()` buffers the complete response; `Config::max_response_size` caps that path. `query_stream()` pulls rows from the network, while `query_stream_blob()` and `query_stream_rows()` stream trailing MAX/LOB columns with bounded memory. The limitations document says MAX columns must be trailing and that a stream must be consumed or cancelled before transaction completion ([`RowStream`](https://docs.rs/mssql-client/latest/mssql_client/struct.RowStream.html), [limitations, buffering/LOB](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/LIMITATIONS.md)). Use `query_stream`, not `query`, for bounded table reads; reject or separately project interleaved MAX columns. The adapter still stops after ResourceFS's own row/byte ceiling and must drain or cancel before reusing the connection.

**Transactions.** `Client::begin_transaction` consumes a ready client into `Client<InTransaction>`, supports an isolation level, and returns the client on `commit` or `rollback`; savepoints are explicit ([`Client` docs](https://docs.rs/mssql-client/latest/mssql_client/struct.Client.html), [transaction module](https://docs.rs/mssql-client/latest/mssql_client/transaction/)). This type-state shape matches `MutationAdapter`: resolve/load can finish before `begin_commit`; commit can perform compare, DML, generated-value read, and commit on one owned connection. The adapter must still prove that cancellation during each step rolls back and that dropping an in-transaction client cannot publish a receipt.

**TLS and authentication.** The driver uses pure-Rust rustls by default, has explicit encrypt/strict/no-TLS settings, and distinguishes `trust_server_certificate` from normal verification ([`Config`](https://docs.rs/mssql-client/latest/mssql_client/struct.Config.html), [README TLS/auth](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/README.md)). SQL authentication and pre-acquired Entra tokens are available without an extra identity feature; managed identity, service principal, and default-chain Entra modes are optional; interactive Entra flows are not built in. Integrated Kerberos/GSSAPI is implemented but explicitly not live-validated. The prototype must test the exact deployment mode rather than treating the feature list as evidence of a working domain configuration ([limitations, auth](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/LIMITATIONS.md)).

**Timeout, cancellation, errors.** `Client::query_with_timeout` and `execute_with_timeout` provide command deadlines; `cancel_handle` returns a clonable handle whose `cancel` sends a server cancellation request. `RowStream::cancel` stops an early stream and leaves the connection reusable. The error enum distinguishes connection, authentication, TLS, protocol, type, response-size, timeout, cancellation, routing, and server failures ([`Client`](https://docs.rs/mssql-client/latest/mssql_client/struct.Client.html), [`CancelHandle`](https://docs.rs/mssql-client/latest/mssql_client/struct.CancelHandle.html), [`RowStream`](https://docs.rs/mssql-client/latest/mssql_client/struct.RowStream.html), [`Error`](https://docs.rs/mssql-client/latest/mssql_client/enum.Error.html)). This is the closest direct match to an `OperationGuard` watcher, but the prototype must exercise cancellation during connect, first-row wait, mid-stream, compare, DML, and commit and then verify connection health.

**Versions, platforms, and cost.** The project documents TDS 7.3–8.0, SQL Server 2008+, Azure SQL, and CI coverage for SQL Server 2017/2019/2022; 2008–2016 and Azure are manually validated, SQL Server 2005 and 32-bit systems are unsupported, and the client is Tokio-only ([README compatibility](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/README.md), [limitations](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/LIMITATIONS.md), [stability](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/STABILITY.md)). The crates are Apache-2.0; TLS is Rust-native and does not require an installed database driver. The published API is intentionally pre-1.0: minor releases may break, old minor lines do not receive security backports, and the project says it is maintained by one maintainer on a best-effort basis ([license/manifest](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/crates/mssql-client/Cargo.toml), [stability policy](https://raw.githubusercontent.com/praxiomlabs/rust-mssql-driver/main/STABILITY.md)). Pinning and an exit plan are mandatory.

**ResourceFS fit.** Strongest available fit. The adapter can map `OperationGuard` cancellation to `CancelHandle`, use `InTransaction` ownership to enforce the commit boundary, and map the typed error enum to stable ResourceFS categories. Remaining work is all source policy: catalog/key discovery, supported-type allowlist, canonical JSON, SHA-256 tag, rowversion/no-rowversion predicates, grants, and bounded continuation.

### 2. Tiberius 0.12.3: established fallback

**Typed values and streaming.** Tiberius is a native async TDS 7.2+ client. Its `ToSql` and `FromSql` documentation covers integer, float, bit, text, binary, UUID, numeric/decimal, XML, and optional chrono/time values ([`ToSql` source](https://raw.githubusercontent.com/prisma/tiberius/master/src/to_sql.rs), [`FromSql` source](https://raw.githubusercontent.com/prisma/tiberius/master/src/from_sql.rs)). `Client::query` returns a `QueryStream`; the stream must be consumed/drained before the connection is reused ([`Client` docs](https://docs.rs/tiberius/latest/tiberius/struct.Client.html), [`QueryStream` docs](https://docs.rs/tiberius/latest/tiberius/struct.QueryStream.html)). This is adequate for typed parameterized SELECT/DML and driver-level streaming, but the adapter must provide its own byte ceilings and dynamic SQL type normalization.

**Transactions and cancellation gap.** The public `Client` method list contains connect/query/execute/simple-query/bulk-insert/close, but no transaction, query-timeout, or cancel handle ([`Client` docs](https://docs.rs/tiberius/latest/tiberius/struct.Client.html)). A transaction therefore requires a parameterless `simple_query("BEGIN TRANSACTION")`/`COMMIT`/`ROLLBACK` batch, and the documented simple-query API warns not to use it with user input. A caller can wrap futures in a Tokio timeout, but that does not prove server cancellation or a reusable connection after dropping a pending read. This is the decisive gap against `OperationGuard` and `MutationAdapter` semantics; the fallback must retire the connection after uncertain cancellation and prove rollback with a fresh connection.

**TLS and authentication.** The default native-tls feature uses OS TLS; rustls is an alternative. `Config` defaults to certificate validation, can add a CA certificate, or can explicitly trust all certificates; it supports SQL Server, Windows/integrated (feature/platform-gated), and AAD token authentication ([`Config` source](https://raw.githubusercontent.com/prisma/tiberius/master/src/client/config.rs), [`AuthMethod` source](https://raw.githubusercontent.com/prisma/tiberius/master/src/client/auth.rs), [Cargo features](https://raw.githubusercontent.com/prisma/tiberius/master/Cargo.toml)). This is a credible security surface, but it brings OS OpenSSL/SChannel/Security Framework dependencies under the default feature and the adapter must own timeout/cancellation policy.

**Versions, maintenance, and cost.** The project README says SQL Server 2022/2019/2017 are CI-tested, 2016 through 2008 should work, and 2005 requires TDS 7.2 mode; it supports Tokio, async-std, and Smol ([README](https://github.com/prisma/tiberius)). Version 0.12.3 is recorded in the manifest and changelog, with MIT/Apache-2.0 licensing ([manifest](https://raw.githubusercontent.com/prisma/tiberius/master/Cargo.toml), [changelog](https://raw.githubusercontent.com/prisma/tiberius/master/CHANGELOG.md)). The dependency footprint is smaller than ODBC deployment but TLS/auth feature choices affect native build dependencies.

**ResourceFS fit.** Good read-only transport fallback; weak mutation fit until a connection wrapper defines cancellation as “send a server-level attention if available, otherwise retire.” Do not hide that policy behind an adapter timeout and then reuse the connection.

### 3. Microsoft `mssql-rs` / `mssql-tds`: technically strong, not yet a production dependency

**Typed values, streaming, and transaction surface.** Microsoft's `mssql-tds` is an async TDS protocol implementation with public `TdsConnectionProvider::create_client`, `TdsClient::execute`, `execute_sp_executesql`, prepared execution, `next_row`, `close_query`, and explicit `begin_transaction`, `save_transaction`, `commit_transaction`, and `rollback_transaction` methods ([crate README](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/lib.rs), [client source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/connection/tds_client.rs)). `RpcParameter` binds a declared `SqlType`, supports named parameters, precision/scale metadata, typed NULLs, and data-at-execution streaming for `nvarchar(max)`, `varchar(max)`, and `varbinary(max)` ([RPC parameter source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/message/parameters/rpc_parameters.rs)). `ColumnValues` has explicit variants for integral/floating/decimal/temporal/money/text/binary/XML/UUID/JSON/vector values ([column values source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/datatypes/column_values.rs)). This is a very good protocol seam, but its low-level API leaves ResourceFS projection and type policy to us.

**Cancellation and TLS.** `ExecuteOptions` carries timeout and an optional `CancelHandle`; `CancelHandle` is backed by a Tokio `CancellationToken`, and the client can send attention with an acknowledgement timeout ([`ExecuteOptions`/client source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/connection/tds_client.rs), [`CancelHandle`/encryption source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/core.rs)). `EncryptionOptions` defaults to strict encryption and exposes certificate trust override, expected certificate hostname, and a pinned certificate path ([core source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/core.rs)). These map unusually well to `OperationGuard` and certificate policy.

**Versions, distribution, and maintenance risk.** The source's `SQLServerVersion` enum recognizes server generations from 2000 through 2022+, but the repository presents the crate as a foundational workspace and does not provide the same published compatibility contract as a crates.io client ([version source](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/src/core.rs), [workspace README](https://github.com/microsoft/mssql-rs)). The crate manifest is `0.1.0`, uses Rust 2024/Tokio/native-tls, and has a broad dependency graph ([manifest](https://raw.githubusercontent.com/microsoft/mssql-rs/main/mssql-tds/Cargo.toml)). Microsoft's open issue #159 states that the only current consumption route is a git dependency, with no semver, immutable registry artifact, or docs.rs release ([issue #159](https://github.com/microsoft/mssql-rs/issues/159)). The temporary `mssql-tds-preview` package confirms that it mirrors upstream and will be yanked when the official package is published ([preview package](https://docs.rs/crate/mssql-tds-preview/latest)).

**ResourceFS fit.** Best API shape after Praxiom for the transport boundary, but not acceptable as the pinned production dependency today. Revisit when Microsoft publishes a versioned crate or when the prototype is explicitly allowed to pin a git revision with supply-chain review.

### 4. `odbc-api` 29.0.0 + Microsoft ODBC Driver: deployment-oriented fallback

**Typed values, parameters, metadata, and streaming.** `odbc-api` is a mostly safe MIT wrapper over `odbc-sys`, tested against Microsoft SQL Server. It supports `Connection::execute`, prepared statements, positional parameter collections, column/row buffers, delayed input parameters, table/column/primary-key metadata, and row-count retrieval ([project README](https://github.com/pacman82/odbc-api), [guide](https://docs.rs/odbc-api/latest/odbc_api/guide/index.html), [`Statement`](https://docs.rs/odbc-api/latest/odbc_api/handles/struct.Statement.html)). `BlockCursor`/`TextRowSet`/`RowVec` let the adapter fetch in batches, and the guide documents streaming arbitrarily large text/binary values through delayed input or buffer APIs ([buffers](https://docs.rs/odbc-api/latest/odbc_api/buffers/index.html), [guide fetching](https://docs.rs/odbc-api/latest/odbc_api/guide/index.html)). The tradeoff is that ODBC conversions are mediated by the installed driver; the adapter must explicitly choose typed buffers and test decimal, date/time, collation, binary, and NULL fidelity.

**Transactions.** The `Connection` API exposes `set_autocommit(false)`, `commit`, and `rollback`; the documentation explicitly says there is no begin method because manual mode starts/continues a transaction with statement execution ([connection source](https://raw.githubusercontent.com/pacman82/odbc-api/main/odbc-api/src/connection.rs)). This can implement MutationAdapter's one-connection transaction if the actor owns the connection and never interleaves borrowers. The connection's `Drop` path attempts rollback on an invalid transaction state, but the adapter must treat cleanup errors as connection retirement rather than assume drop is an acknowledgement.

**Timeout and cancellation.** `Connection::execute` accepts a query timeout and maps it to `SQL_ATTR_QUERY_TIMEOUT`; the docs state Microsoft SQL Server supports it. Polling mode (`execute_polling`) is available, but the guide warns that support is driver-dependent and that an apparently asynchronous call may block the entire thread ([connection docs/source](https://raw.githubusercontent.com/pacman82/odbc-api/main/odbc-api/src/connection.rs), [async caveat](https://docs.rs/odbc-api/latest/odbc_api/guide/index.html)). The public `Statement` trait exposes timeout, async polling, fetching, and `complete_async`, but no `cancel`/`SQLCancel` method ([`Statement`](https://docs.rs/odbc-api/latest/odbc_api/handles/struct.Statement.html), [statement source](https://raw.githubusercontent.com/pacman82/odbc-api/main/odbc-api/src/handles/statement.rs)). Therefore a ResourceFS actor cannot implement `OperationGuard` cancellation by merely dropping a future; it needs an explicit raw-ODBC cancellation design or to kill/retire the worker connection and prove no mutation remains in flight.

**TLS, authentication, versions, and cost.** `odbc-api` delegates TLS, authentication, SQL Server version support, and certificate policy to the selected driver. Microsoft's ODBC Driver for SQL Server is a separately installed native component with Linux/macOS/Windows documentation and current 18.x releases ([Microsoft ODBC driver](https://learn.microsoft.com/en-us/sql/connect/odbc/microsoft-odbc-driver-for-sql-server?view=sql-server-ver17), [installation](https://learn.microsoft.com/en-us/sql/connect/odbc/download-odbc-driver-for-sql-server?view=sql-server-ver17), [connection keywords](https://learn.microsoft.com/en-us/sql/connect/odbc/dsn-connection-string-attribute?view=sql-server-ver17)). The Rust crate is MIT, but it requires an ODBC driver manager (unixODBC on Linux/macOS or the built-in Windows manager) and a compatible SQL Server driver; `vendored-unix-odbc` has separate LGPL licensing implications ([README](https://github.com/pacman82/odbc-api), [manifest](https://raw.githubusercontent.com/pacman82/odbc-api/main/odbc-api/Cargo.toml)). This is operationally more expensive than a pure-Rust TDS client and must be represented as a required runtime dependency/probe.

**Maintenance.** The current changelog records 29.0.0 on 2026-07-19 and frequent prior releases, which is a positive maintenance signal, but the ODBC manager and Microsoft driver remain independent versioned components ([changelog](https://raw.githubusercontent.com/pacman82/odbc-api/main/CHANGELOG.md)).

**ResourceFS fit.** Viable only with a dedicated blocking actor, bounded channels, strict driver/version pinning, and a connection-retirement cancellation policy. It is a good compatibility fallback where Microsoft driver behavior/authentication is more important than one-binary deployment; it is not the smallest proof of the TDS boundary.

### 5. `sqlx-mssql-odbc` 0.1.8: young wrapper, not the fallback

This crate demonstrates a SQLx-compatible facade over ODBC and documents `MssqlConnection`, async queries, parameters, transactions, optional type features, and Linux/macOS/Windows installation requirements ([crate docs](https://docs.rs/sqlx-mssql-odbc/latest/sqlx_mssql_odbc/), [repository README](https://github.com/strawberyy-coconut/sqlx-mssql-odbc)). Its source owns each ODBC connection in a dedicated blocking `ConnectionActor` and streams rows through a bounded channel ([actor source](https://raw.githubusercontent.com/strawberyy-coconut/sqlx-mssql-odbc/main/sqlx-mssql-odbc-core/src/connection/actor.rs), [helpers source](https://raw.githubusercontent.com/strawberyy-coconut/sqlx-mssql-odbc/main/sqlx-mssql-odbc-core/src/connection/helpers.rs)). That is a workable architecture in principle.

The source also explains why it is not the first ODBC choice: actor `Execute` calls ODBC execute/prepare directly, while `MssqlConnectOptions` exposes buffer sizes, statement-cache settings, `encrypt`, and `trust_certificate` but no query-timeout or cancellation setting ([actor](https://raw.githubusercontent.com/strawberyy-coconut/sqlx-mssql-odbc/main/sqlx-mssql-odbc-core/src/connection/actor.rs), [options](https://raw.githubusercontent.com/strawberyy-coconut/sqlx-mssql-odbc/main/sqlx-mssql-odbc-core/src/options.rs)). If the async consumer drops the result receiver, the actor observes a failed send only after the blocking ODBC call/fetch path returns; dropping the SQLx future is not server cancellation. Its `MssqlValueKind` also has a deliberately small value set and converts decimal through text/`f64` paths, which requires precision tests before it can represent an authoritative ResourceFS row ([value source](https://raw.githubusercontent.com/strawberyy-coconut/sqlx-mssql-odbc/main/sqlx-mssql-odbc-core/src/value.rs)). The repository README says CI currently verifies Linux only and macOS/Windows are untested ([README](https://github.com/strawberyy-coconut/sqlx-mssql-odbc)). Direct `odbc-api` avoids adding this second, young mapping/actor layer.

### 6. Ruled-out or non-client routes

* **SQLx mainline:** the official README explicitly says MSSQL was removed prior to 0.7 pending a complete driver rewrite, while current support lists PostgreSQL, MySQL/MariaDB, and SQLite ([README](https://github.com/launchbadge/sqlx)). An SQLx API cannot be selected without a separate MSSQL implementation.
* **`ms-tds`:** its own status says pre-alpha; row/COLMETADATA decoding is not implemented and a query can return an empty result set even when the server sends rows ([docs](https://docs.rs/ms-tds/latest/ms_tds/index.html)).
* **Legacy `odbc`:** the upstream README marks the project unsupported and says maintainers may be needed ([README](https://github.com/Koka/odbc-rs)).
* **`tds-protocol`:** useful building block but intentionally IO/runtime agnostic and primarily consumed by `mssql-client`; it is not a connection/transaction/cancellation client ([crate docs](https://docs.rs/crate/tds-protocol/latest)).
* **`mssql-tds-preview`:** packageable but intentionally temporary and slated for yanking ([docs](https://docs.rs/crate/mssql-tds-preview/latest)).

## Prototype plan and falsification checks

The prototype should be a transport-boundary probe, not a partial production adapter. It must use only fixed, generated SQL for known fixtures; arbitrary caller SQL is out of scope. Run the same fixture through the selected client and, where available, the exact pinned `sqlcmd` binary as a read-only oracle.

### Primary `mssql-client` probe

1. **Connect and security:** SQL Server 2017, 2019, and 2022 containers or test instances; one Azure SQL target if available. Test strict TLS with a trusted CA, hostname mismatch, an untrusted CA, and an explicit development-only trust override. Test SQL login and one required Entra/integrated mode. **Falsify** if an invalid certificate succeeds, required encryption is silently downgraded, or auth errors cannot be classified without credential leakage.
2. **Catalog and identity:** query named catalog columns and PK metadata for scalar and composite keys, nullable/non-nullable columns, identity/computed columns, `rowversion`, generated defaults, and unsupported types. Verify component-wise identifier quoting with names containing `]`, spaces, Unicode, reserved words, and case differences. **Falsify** if metadata is guessed, an unsupported/no-PK table is exposed, key order differs from `key_ordinal`, or an identifier/value can alter SQL structure.
3. **Typed round trip:** insert and read a fixture covering all admitted integer/float/bit/text/binary/UUID/date/time/datetimeoffset/decimal/XML/NULL cells, including empty strings/bytes, min/max values, scale, collation, and a large MAX value. Hash the adapter's canonical JSON bytes and compare repeated reads. **Falsify** on any lossy conversion, decimal precision change, NULL/empty conflation, unstable column order, or tag change without authoritative content change. Reject documented unsupported/spatial/large-decimal types explicitly.
4. **Bounded streaming:** run a result larger than the ResourceFS byte/row limit and a multi-GB or near-limit MAX cell. Use `query_stream`/blob streaming, stop at the limit, cancel/drain, and reuse or retire the connection. **Falsify** if resident memory scales with the complete result, a stream cannot be stopped without wedging the client, or a trailing/interleaved MAX layout is mis-decoded.
5. **Mutation transaction:** on one connection, begin at the selected isolation level, load/compare, perform fixed parameterized INSERT/UPDATE/DELETE, retrieve generated values, and commit. Exercise duplicate key, NOT NULL/check/foreign-key/type errors and cancellation before DML, during DML, after DML before generated-value read, and before commit. **Falsify** if any failed case leaves a row or partial generated state, publishes a tag, or returns a connection that still carries an open transaction/batch.
6. **Optimistic concurrency:** test conditional replace/delete for a `rowversion` table and a table without `rowversion`, with a concurrent writer between load and commit. **Falsify** if stale state succeeds, zero affected rows are treated as success, a no-rowversion predicate mishandles NULL, or a ResourceFS SHA-256 tag is used as the sole database compare predicate.
7. **OperationGuard bridge:** create a guard watcher that calls the driver's cancel handle, and test cancellation while waiting for connect, first row, subsequent row, stream limit, and mutation. **Falsify** if cancellation only stops the caller while server work continues, if the server does not acknowledge/rollback, or if the adapter cannot prove connection retirement before reuse.
8. **Bounds/error mapping:** force response-size, timeout, protocol, TLS, authentication, permission, unsupported-type, conversion, server, and cancellation errors. Map each to a stable ResourceFS category and redact credentials/SQL values. **Falsify** if errors require parsing localized text, expose secrets, or collapse conflict/timeout/cancel/permission into “source unavailable.”

### ODBC fallback probe

Run the same read-only catalog/type/TLS/auth fixtures with direct `odbc-api` and the exact Microsoft ODBC Driver/manager versions intended for deployment. Require an actor with bounded channels and a tested raw `SQLCancel` or “retire connection” strategy; do not infer cancellation from a dropped receiver. Test `SQL_ATTR_QUERY_TIMEOUT`, manual-commit rollback on actor shutdown, driver decimal/date/Unicode conversion, driver bitness, and DSN/connection-string credential redaction. **Falsify** this route for the intended deployment if polling blocks the executor thread, timeout does not interrupt the SQL Server operation, connection drop can leave a mutation in flight, or native-driver installation/version drift violates the deployment contract.

### Microsoft route re-evaluation

If Microsoft publishes `mssql-tds` with a semver package, docs, and a stable support statement, repeat the primary probe against it. Its current `ExecuteOptions`, `CancelHandle`, typed `RpcParameter`, streamed MAX parameters, and explicit transaction methods already satisfy the shape of the desired transport boundary, but the current git-only distribution is itself a production supply-chain failure. **Falsify** adoption until registry publication, exact API pinning, and the same live version/TLS/auth/cancellation matrix pass.

### `sqlcmd` oracle rules

Pin the exact Go or ODBC `sqlcmd` variant and version, issue only fixed read-only catalog/SELECT statements, impose stdout/stderr and row-size ceilings, and compare parsed scalar results with the in-process client. Do not use `-v` textual substitution for ResourceFS values, do not accept arbitrary SQL, and do not treat process termination as a typed cancellation result. Microsoft documents that normal output is formatted text and that the variants/options differ; `FOR JSON` can split large results across rows, and the documented `:XML` output behavior is not portable to Linux/macOS ([utility](https://learn.microsoft.com/en-us/sql/tools/sqlcmd/sqlcmd-utility?view=sql-server-ver17), [commands](https://learn.microsoft.com/en-us/sql/tools/sqlcmd/sqlcmd-commands?view=sql-server-ver17), [installation](https://learn.microsoft.com/en-us/sql/tools/sqlcmd/sqlcmd-download-install?view=sql-server-ver17), [FOR JSON](https://learn.microsoft.com/en-us/sql/relational-databases/json/format-query-results-as-json-with-for-json-sql-server?view=sql-server-ver17)).

## Resulting adapter boundary

The selected client must sit behind a ResourceFS-owned interface that exposes only the operations needed by the source:

* connect a configured mount (server/database/auth/TLS/timeouts),
* discover visible schemas/tables/columns/PK order with named catalog projections,
* execute a generated parameterized read with a bounded row stream,
* execute compare + DML + generated-row read in one explicit transaction,
* cancel/drain/retire with an observable outcome,
* return typed driver errors for mapping to ResourceFS categories.

The adapter must never let a path segment become raw SQL. The recommended logical address remains a configured SQL Server mount plus schema/table/key; a filesystem `.mdf` path is an ordinary file, not an implicit attach or database session ([attach semantics](https://learn.microsoft.com/en-us/sql/relational-databases/databases/attach-a-database?view=sql-server-ver17), [LocalDB](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql/sqlclient-support-localdb?view=sql-server-ver17)).

Rows become deterministic JSON only after source-local metadata validation. Select explicit columns in one documented order, choose a documented encoding for binary/decimal/temporal/UUID/XML values and NULLs, hash those exact UTF-8 bytes into ResourceFS's `sha256:` Version Tag, and reject lossy/unsupported types. `FOR JSON PATH` may help with a server-side projection, but SQL Server's output can be split into multiple result rows and its NULL/property defaults must be made explicit; it is not a substitute for the adapter's canonicalization policy ([FOR JSON](https://learn.microsoft.com/en-us/sql/relational-databases/json/format-query-results-as-json-with-for-json-sql-server?view=sql-server-ver17), [OPENJSON](https://learn.microsoft.com/en-us/sql/relational-databases/json/convert-json-data-to-rows-and-columns-with-openjson-sql-server?view=sql-server-ver17)).

## Residual uncertainty

The selection remains conditional on facts no library documentation can establish for ResourceFS:

* the exact admitted SQL type subset and canonical JSON encoding, especially decimal precision, temporal offsets, binary, XML, `sql_variant`, spatial/CLR values, and generated columns;
* whether editable row JSON includes identity/computed/rowversion columns and how replacements handle server-generated values;
* whether no-rowversion tables can guarantee an authoritative projection of every changeable column;
* the required isolation level for deterministic multi-page enumeration under concurrent writes;
* whether `mssql-client` cancellation leaves every target SQL Server version's connection reusable, or whether the adapter must retire the connection;
* live integrated/Kerberos and Entra authentication behavior in the deployment's OS/container images;
* SQL Server 2008–2016 and Azure behavior beyond the candidates' stated CI/manual coverage;
* pool reset/session state, especially after cancellation, timeout, routing redirect, and an abandoned stream;
* exact dependency/SBOM policy for pre-1.0 crates and whether future Microsoft publication changes the preferred client;
* whether native ODBC manager/driver installation is acceptable as a supported ResourceFS runtime fallback.

These are prototype gates, not reasons to silently narrow the contract. Until the gates pass, expose only a read-only bounded source or report the SQL Server source as unavailable/unsupported; do not ship mutation behind an unproven cancellation or type-conversion path.
