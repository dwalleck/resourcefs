# Consolidate MCP servers behind one self-describing namespace

ResourceFS's product thesis is consolidation: one namespace with five fixed tools replaces a per-server zoo of MCP tool schemas, so a source's roadmap priority is measured by the MCP server or bespoke tool class it retires from an agent's configuration, not by Oh My Pi coverage. Sources that retire a server (GitHub with its Creation Targets, vault/memory, HTTPS reader mode, SQLite) precede enhancements that retire nothing (structural summaries, SSH, agent exports). The model-controlled tool surface is permanently capped at the five `rfs_*` tools; every future capability mounts as a Path Reference — Creation Targets, projections, device-shaped paths driven by `rfs_read`/`rfs_write` — never as a new tool, preserving constant schema cost as sources grow. Because harnesses do not reliably surface server instructions, the namespace must describe itself from inside: reading `rfs://` or a bare scheme root returns a bounded catalog of mounted sources, their reference grammar, and one example spelling each, so an unconfigured harness can discover the address space through the tools alone. The namespace deliberately covers resource-shaped capabilities — information and stateful documents, including actions whose result is a resource — and does not absorb imperative tool surfaces such as browser automation or command execution.
