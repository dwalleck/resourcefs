## Removed invariants

This change is additive at the product surface but subtractive at three existing guards.

1. **GitHub address parsing currently forbids `/new`.** That silently guarantees every parsed GitHub address denotes readable upstream state and carries numeric object identity. Adding typed Creation Target variants makes write-only, non-readable addresses possible. C2 preserves exhaustive parsing/canonicalization and explicit read refusal; C14 preserves non-target refusal.
2. **Compiled mutation dispatch currently rejects every Issue/PullRequest address.** That silently guarantees no GitHub adapter path can send PATCH/POST and no read cache can become stale through local mutation. C5/C14 preserve policy/projection refusal; C13 restores cache coherence; C15 preserves one bounded egress seam.
3. **`MutationEngine::write` currently assumes authored bytes are the committed Resource, pre-reserves a seen snapshot, and returns the input target as canonical.** That guarantees a content tag/coverage and target-stable receipt for filesystem/local writes. Creation Targets and response-authoritative Fields remove that universal assumption. C7 introduces an exhaustive target/outcome sum, C9/C10 preserve correct tags/references, and C17 proves authored-text behavior remains unchanged.

Still safe: per-canonical-Resource lock ordering remains in core; `OperationGuard::begin_commit` continues to mask cancellation only after commit entry; GitHub `rfs_edit` remains unsupported, so remote Fields never enter seen-region snapshot authority.

## Placement

### Typed GitHub Creation Target addresses

- **Owner:** `resourcefs-core::reference`; it already owns `IssueResource`, `PullRequestResource`, child-ID newtypes, parsing, canonical rendering, and exhaustive resource matches.
- **New seam:** no new seam. Add explicit `New` and `CommentsNew` variants to the existing address sums; every downstream match stays exhaustive.
- **Forbidden:** no string suffix re-parsing in `resourcefs-sources`, no `path.ends_with("/new")`, and no source-owned duplicate reference grammar.

### Operation ID and Path-Session journal

- **Owner:** `resourcefs-core::mutation` owns validated `OperationId` and journal transition vocabulary; `resourcefs-core::session` owns storage/lifetime because one Path Session bounds deduplication.
- **Competing seam A:** source-neutral `PathSession::begin_mutation_operation(OperationId, target, Arc<str>)` returning an exhaustive lease/state transition object. High depth: all adapters get exact-byte identity, concurrency, conflict, count/byte ceilings, disconnect, and wait semantics through one interface.
- **Competing seam B:** store GitHub-specific journal entries through generic session cache keys. Smaller initial type change, but journal invariants become convention strings, cache quota/eviction can destroy returned deduplication state, and a future remote Creation Target would duplicate the state machine.
- **Decision:** A. `WriteRequest` and journal share the same `Arc<str>`; entries compare canonical target and exact content bytes, may cache SHA-256 only as a fast negative check, and charge retained bytes to the existing 256 MiB Path-Session quota. The 10,000-entry ceiling is additional. This avoids a second content copy without weakening exact equality.
- **Forbidden:** no static/process-global journal, no cache-backed journal, no eviction of live entries, no raw `String` operation IDs past construction, and no digest-only equality.

### Shared mutation target/outcome interface

- **Owner:** `resourcefs-core::mutation`; the common engine already owns target resolution, access selection, locks, version comparison, cancellation fencing, and receipts.
- **Competing seam A:** extend `MutationTarget` with an exhaustive mode (`AuthoredText`, `AuthoritativeText`, `CreationTarget`) and change `MutationAdapter::commit` to return a typed `MutationCommitOutcome` or typed conclusive/unknown failure.
- **Competing seam B:** bypass `MutationEngine` for GitHub writes in `resourcefs-mcp` or `CompiledSources`, returning source-specific receipts.
- **Decision:** A. It keeps one deep mutation interface and lets the compiler force every adapter/test to handle new outcomes. B duplicates grants, locks, operation journal, cancellation, and rendering and leaks GitHub behavior across modules.
- **Forbidden:** no `Any`/downcast payloads, no GitHub DTO in core, no boolean target-mode flags, no MCP-layer mutation orchestration. Mode/outcome mismatch is an internal `source_unavailable` error, never a fabricated receipt.

`AuthoredText` preserves current pre-commit seen reservation and input-derived tag/coverage. `AuthoritativeText` supports update only, publishes the adapter-returned authoritative Version Tag with no seen coverage. `CreationTarget` supports create only, requires an operation lease, returns the response-derived canonical Path Reference, and has no Version Tag/coverage. `MutationCommitFailure::{Conclusive, Unknown}` tells the journal whether identical caller-initiated retry is permitted or the ID is blocked; both carry `ResourceError`.

### HTTP mutation transport

- **Owner:** `resourcefs-sources::http`; it is the workspace's only HTTP egress module and already owns resolver/address policy, credentials, TLS, cancellation, deadlines, response ceilings, and redirect policy.
- **Competing seam A:** make `HttpRequest` carry a validated method/body and redirect mode; keep redirecting and non-redirecting reqwest clients private inside one `HttpSubstrate`, built from the same allowlist/resolver/TLS/timeout configuration. Mutation requests select the non-redirecting client and call one-attempt fetch directly.
- **Competing seam B:** let `GithubSource` construct reqwest requests/clients or manually follow/refuse redirects after using the GET-only substrate.
- **Decision:** A. Per-request redirect behavior is a reqwest-client property; two private pools are the narrow cost of preserving the existing read redirect contract while guaranteeing zero mutation redirects. Both remain one module/interface/policy implementation. B creates a second egress path and can bypass credential/address/response bounds.
- **Forbidden:** no public reqwest types, no source-created client, no mutation use of GitHub's read retry loop, no credential header in `HttpRequest`, no automatic redirect/retry.

### GitHub mutation implementation

- **Owner:** private `resourcefs-sources::github::mutation` behind `GithubSource`'s `MutationAdapter` implementation. A private file is warranted because current `github/mod.rs` is already the large read implementation; the external module interface remains `GithubSource`.
- **New seam:** no external seam. Private typed request/response DTOs live with `github::wire`; the strict frontmatter parser and mutation endpoint/response validation remain private implementation.
- **Forbidden:** no generic YAML dependency or full YAML parser for the approved subset; no labels/assignees/state/review fields in request DTOs; no GraphQL; no second HTTP policy path; no upstream error-body rendering.

Resolve applies readable allowlisting and repository create/update grants before network. Load uses an unconditional GET for `AuthoritativeText`. Commit PATCHes exactly one title/body/comment field or POSTs exactly one approved creation body, validates returned repository/object/parent identity, maps the response to a typed outcome, and clears the session's `github-http` cache namespace only after success.

### Compiled dispatch, MCP surface, and fixtures

- **Owner:** `resourcefs-sources::compiled` adds GitHub mutation routing; `resourcefs-mcp::server` owns optional `operationId` deserialization/schema/tool text; `resourcefs-mcp::render` continues to render source-neutral receipts; `resourcefs-sources::tests::support::tls` owns method/body/stateful fake observations.
- **New seam:** the fake router gains a typed request observation (method, target, headers, complete bounded body) and may drop a response after consuming a request. This is test-only variation at the existing fixture seam.
- **Forbidden:** no GitHub-specific MCP tool/output type, no protocol error for operational failure, no test assertion against private helper order, and no feature test that treats a fixture declaration as its own oracle.

## Claims

- **C1:** The six selected GitHub REST mutations use the empirically validated methods, paths, request fields, success statuses, response types, and no conditional `If-Match` contract.
- **C2:** `/new` and `comments/new` are explicit typed address variants that render canonically and return `unsupported_projection` on read.
- **C3:** `OperationId` admits exactly 1–128 case-sensitive `[A-Za-z0-9._:-]` characters, and every invalid or non-Creation-Target use fails before adapter/network access.
- **C4:** The Path-Session journal binds one ID to one canonical target and exact content bytes, coalesces identical in-flight calls, enforces the 10,000-entry and shared 256 MiB byte ceilings without eviction, rejects conflicts even under forced fingerprint collision, and isolates sessions.
- **C5:** Target mode, metadata presence, readable allowlisting, and repository grants form one exhaustive pre-network create/update matrix.
- **C6:** The creation parser accepts only the approved one-line YAML subset, LF/CRLF delimiters, exact post-delimiter Markdown bytes, and the approved empty-field matrix.
- **C7:** The common mutation interface represents authored text, authoritative text, and Creation Targets as exhaustive modes/outcomes without source-specific core types.
- **C8:** Existing GitHub Field replacement performs one uncached authoritative GET, compares the supplied Version Tag, and PATCHes exactly the selected field under the canonical Resource lock.
- **C9:** A successful Field receipt uses the validated response field's Version Tag and publishes no seen coverage; failed/unknown responses publish neither a new tag nor seen coverage.
- **C10:** Successful comment/issue/PR creation preserves the approved content bytes in its request, returns the validated response-derived canonical reference, and publishes no Version Tag or seen coverage.
- **C11:** GitHub mutations make one transmitted request, follow zero redirects, ignore `Retry-After` for retry purposes, and classify unvalidated possibly transmitted creation outcomes as journal-blocking unknown.
- **C12:** Mutation status classification matches the approved matrix and never includes upstream body text or credentials in errors.
- **C13:** A successful GitHub mutation clears only the complete `github-http` namespace in its Path Session before the receipt; failures clear nothing.
- **C14:** Aggregates, collections, reviews, inline comments, diffs, unsupported segments, deletion, and every GitHub `rfs_edit` remain non-mutable with zero mutation egress.
- **C15:** All GitHub PATCH/POST requests reuse `HttpSubstrate` policy, credential, TLS, timeout, cancellation, request/response ceiling, and address checks without exposing reqwest outside the HTTP module.
- **C16:** The public `rfs_write` schema carries optional `operationId`, and plain-text/structured receipts and errors agree on canonical reference, null/non-null tag, operation, and category.
- **C17:** Existing filesystem/local authored-text create/replace/edit/delete/move receipts, snapshots, locks, and cancellation behavior remain byte-for-byte/semantically unchanged.
- **C18:** Conclusive creation rejection permits only an identical caller-initiated retry; unknown blocks the ID; disconnect drops journal authority; Field unknowns require a fresh read.
- **C19:** Success responses with wrong repository/object/parent identity, missing IDs/fields, malformed JSON, truncation, wrong success status, or oversize bodies never yield a receipt and become unknown when creation may have committed.
- **C20:** GitHub mutation JSON contains only the selected field or approved creation keys; labels, assignees, state, review, and inline-comment keys are unrepresentable in private request DTOs.
- **C21:** Source/repository grant conversion and checked-in profile schema continue to support GitHub create/update and reject delete without widening read authority.
- **C22:** Core remains free of reqwest/rmcp/source dependencies, and source-specific mutation behavior stays behind the Source Adapter seam.
