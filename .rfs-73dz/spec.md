# Spec: Versioned workspace text mutation

## Request (verbatim)
> claim and implement rfs-73dz

## What this is

ResourceFS adds the two remaining fixed MCP tools for mutation of authoritative Workspace text. A coding agent can create, replace, line-edit, delete, or move a contained workspace Resource only under explicit operator grants, with prior-state checks and failure atomicity.

## Roles

- **Coding agent**: invokes `rfs_write` and `rfs_edit`, supplies prior Version Tags and patch coordinates, and observes structured success or stable operational failure.
- **ResourceFS operator**: selects Workspace Roots and independently grants create, update, and delete authority in the Server Profile; sees no new implicit authority.

## Behavior

### Create workspace text
- **Given**: a Path Reference resolves to a missing contained destination under a Workspace Root whose create grant is true.
- **When**: a coding agent calls `rfs_write` with that Path Reference and JSON UTF-8 string content, without `ifVersion`.
- **Then**: ResourceFS creates exactly one regular text Resource atomically when its parent directory exists and content is at most 64 MiB, then returns a compact `created` receipt whose `displayedRanges`/`displayedEof` cover the full authored content under the new Version Tag, which the Path Session records as seen; a read observes exactly the submitted bytes. A missing parent returns `not_found` without creating directories.

### Replace workspace text
- **Given**: a Path Reference resolves to an existing contained regular UTF-8 text Resource under a Workspace Root whose update grant is true, and the coding agent has its current Version Tag.
- **When**: the coding agent calls `rfs_write` with replacement content and that tag in `ifVersion`.
- **Then**: ResourceFS compares the authoritative content immediately before commit, atomically replaces it only when the tag still matches, preserves ordinary permissions, and returns a compact `replaced` receipt with the new content-derived Version Tag and full-coverage `displayedRanges`/`displayedEof` under it, which the Path Session records as seen.

### Expose editable coordinates
- **Given**: a direct workspace read returns one or more original source-line ranges, possibly bounded, for one canonical Resource and authoritative Version Tag.
- **When**: ResourceFS renders the successful `rfs_read` result.
- **Then**: structured output includes inclusive `displayedRanges` entries shaped as `{startLine, endLine}` for only fully displayed original lines plus `displayedEof: true` only when all bytes through EOF were displayed; non-empty text emits `Displayed Lines: <ranges|none>` and `Displayed EOF: <true|false>` adjacent to the existing `[canonical-reference#Version-Tag]` header while both text body and structured `content` remain byte-exact. Structured `mutable` is `true` exactly when the Resource is workspace text under a Workspace Root whose update grant is true and the path traverses no contained link; catalogs, artifacts, non-text Resources, and ungranted roots report `false`. When the caller requests the numbered projection (a read-time rendering option whose exact spelling is fixed in design; it changes rendering only, never Resource identity), the text body prefixes every displayed line with its original line number as `N:` in OMP's style while structured `content` stays byte-exact, and the Version Tag, `displayedRanges`, `displayedEof`, and seen-region recording are identical to the unnumbered read of the same selection.

### Apply a hashline edit
- **Given**: the same live Path Session previously displayed editable regions of an existing workspace text Resource and recorded their union under its authoritative Version Tag, and update is granted.
- **When**: the coding agent calls `rfs_edit` with one document headed by `[<canonical-reference>#<Version-Tag>]` (the full current Version Tag or a unique prefix of at least 12 hex characters of a tag recorded for that Resource in the live Path Session), followed by valid `PUT N.=M:`, `PUT <N:`, `PUT >N:`, `PUT >$:`, or `CUT N.=M` hunks that target only displayed lines/gaps; every body row follows OMP `+TEXT` conventions and every coordinate names the original snapshot.
- **Then**: ResourceFS rejects overlaps before mutation, applies all hunks against the immutable original-coordinate space, preserves untouched bytes and newline spelling, validates the at-most-64-MiB result, atomically replaces the Resource, and returns a compact `edited` receipt with its new Version Tag plus `displayedRanges`/`displayedEof` under that tag — the line-delta remap of the prior same-tag seen union plus the rows the edit authored — which the Path Session records as seen so a consecutive edit needs no intervening read.

### Delete workspace text
- **Given**: an existing contained workspace text Resource, its exact prior-read Version Tag and snapshot, and delete authority.
- **When**: the coding agent submits one `[<canonical-reference>#<Version-Tag>]` document whose sole operation is `REM` through `rfs_edit`.
- **Then**: ResourceFS atomically deletes that Resource and returns a compact `deleted` receipt with no Version Tag; no empty `PUT`, empty `rfs_write`, or other syntax means deletion.

### Move workspace text
- **Given**: an existing contained source text Resource, its exact prior-read Version Tag and snapshot, a missing contained destination in the same Workspace Source, delete authority for the source, and create authority for the destination.
- **When**: the coding agent submits one `[<canonical-reference>#<Version-Tag>]` document whose sole operation is `MV <destination-Path-Reference>` through `rfs_edit`.
- **Then**: ResourceFS performs one atomic no-clobber move, preserves ordinary permissions, and returns a compact `moved` receipt naming source and destination plus the unchanged content-derived Version Tag. Existing destinations return `version_conflict`; cross-source or cross-filesystem destinations return `unsupported_mutation`; neither path changes on failure.

### Reject unsafe mutation
- **Given**: a mutation is malformed, stale, snapshot-unseen, internally conflicting, unauthorized, outside containment, aimed at an immutable catalog or artifact, non-text, or otherwise unsupported.
- **When**: the coding agent invokes `rfs_write` or `rfs_edit`.
- **Then**: ResourceFS returns the specified stable operational category (`invalid_patch`, `permission_denied`, `version_conflict`, `not_found`, `limit_exceeded`, `unsupported_mutation`, `source_unavailable`, or `cancelled`), commits none of that Resource mutation, and leaves authoritative state unchanged.

### Serialize concurrent mutation
- **Given**: two or more mutation calls resolve to the same canonical workspace Resource.
- **When**: their validation and commit intervals overlap.
- **Then**: ResourceFS serializes those intervals per canonical Resource, exactly one stale competing Version Tag can commit, and every losing call returns `version_conflict` without overwriting the winner.

### Reject catalog and artifact mutation
- **Given**: any grants and either catalog reference (`rfs://`, `rfs://workspace`) or any `artifact://` reference.
- **When**: the coding agent invokes `rfs_write` or `rfs_edit` against that immutable Resource.
- **Then**: ResourceFS returns `permission_denied` and leaves all authoritative state unchanged; typed catalog and artifact addresses are rejected before any source mutation path runs.

## Success criteria

- **Binary / structural / security**: create requires only the create grant; replacement and `PUT`/`CUT` require update; `REM` requires delete; `MV` requires source delete plus destination create, checked by direct filesystem adapter contract tests covering every grant combination and policy-before-state precedence.
- **Binary / structural / security**: create-if-missing and replace-if-current follow omitted/present `ifVersion`; every edit/delete/move header carries the full current Version Tag or a unique prefix of at least 12 hex characters of it (shorter or ambiguous prefixes are `invalid_patch`; prefixes matching no recorded tag are `version_conflict`), checked by exact-state, stale-state, missing-state, prefix, and same-content retry tests.
- **Binary / structural / security**: `created`, `replaced`, and `edited` receipts report `displayedRanges`/`displayedEof` under the new Version Tag (full coverage for authored content; the line-delta remap of the prior seen union plus authored rows for edits), the Path Session records them, and a consecutive same-session edit against those ranges succeeds without an intervening read, checked by engine contract tests including shifted-coordinate and EOF-carry cases.
- **Binary / structural / security**: `rfs_read` preserves byte-exact content while reporting exact inclusive `displayedRanges` for fully displayed lines and `displayedEof` only after complete tail display; same-tag reads union only within one live Path Session, checked by full, bounded, disjoint-range, partial-line, final-page, cross-tag, cross-session, artifact, and invalidated-session tests.
- **Binary / structural / security**: the parser accepts only the approved range/gap grammar and OMP body rows, applies all coordinates against the original snapshot, and rejects overlaps, unseen targets, multiple headers, block-star forms, and registers as `invalid_patch`, checked by parser golden tests and teaching-error assertions.
- **Binary / structural / security**: `REM` is the only delete form and `MV` is atomic no-clobber within one filesystem, checked by empty-content, existing-destination, cross-source, cross-filesystem, and injected move-failure tests.
- **Binary / structural / security**: malformed, stale, unseen, conflicting, unauthorized, linked-path, catalog, artifact, non-text, over-limit, cancelled-before-commit, and I/O-failing mutations preserve prior authoritative state, checked by failure-injection adapter and MCP tool contracts.
- **Binary / structural / security**: replacement/edit preserve untouched bytes, LF/CRLF/mixed newline spelling, and ordinary permissions while leaving richer metadata outside the guarantee, checked by byte-for-byte and platform-native permission fixtures.
- **Binary / structural / security**: overlapping mutations for one canonical Resource serialize; a gated race observes one commit, one `version_conflict`, no torn content, and ordered source/destination locking for `MV`.
- **Binary / structural / security**: once an atomic commit starts, cancellation is masked and the actual result is returned, checked by gates immediately before and during commit.
- **Binary / structural / security**: successful tools return the approved compact operation receipt as object-rooted structured content and equivalent non-empty text, checked by schema and stdio MCP contract tests.
- **Quantitative**: exactly 64 MiB of source content, resulting content, or patch input is accepted and one byte over returns `limit_exceeded` before commit without allocation materially beyond the bounded input/result buffers, measured by direct exact-limit/one-over tests.
- **Binary / structural / security**: workspace creation, replacement, deletion, and no-clobber move provide atomic visibility on Linux, macOS, and Windows, checked by platform-native direct adapter tests plus the empirical probe recorded by this change.
- **Quantitative**: the hashline parser completes without crash, panic, or unbounded allocation for every generated input during a 60-second `cargo-fuzz` run, measured by the dedicated hashline fuzz target on the development platform.
- **Binary / structural / security**: the hashline parser, seen-region union registry, Version Tag compare and per-canonical-Resource serialization, receipt rendering, and operational-error precedence are source-neutral (no filesystem, `cap-std`, or MCP types) and are directly tested against a fake mutation adapter; the filesystem adapter supplies only contained open/create/replace/move/delete primitives behind that seam, checked by core engine contract tests plus the existing architecture fence.
- **Binary / structural / security**: `rfs_read` reports `mutable: true` exactly for workspace text under an update-granted root with no contained link on its path and `false` for catalogs, artifacts, non-text Resources, and ungranted roots, checked by direct read contract tests across grant combinations.
- **Binary / structural / security**: the numbered read projection renders `N:`-prefixed displayed lines in text only, leaves structured `content` byte-exact, and yields the same Version Tag, `displayedRanges`, and seen-region union as the unnumbered read, checked by golden read fixtures and a same-tag union test mixing numbered and unnumbered reads.
- **Binary / structural / security**: `artifact://` mutation attempts return `permission_denied` with no state change, checked alongside the catalog rejection contracts.
- **Binary / structural / security**: `rfs_write` and `rfs_edit` descriptions begin with the `rfs_read`/`rfs://` discovery cue inherited from rfs-ewh2 and summarize the accepted grammar and header binding, checked by the existing tools/list description assertions extended to five tools.
- **Binary / structural / security**: client-declared roots inherit grants only from a profile-declared root with the identical canonical path, while CLI roots and non-matching client roots are read-only, checked by authority-refresh contract tests across matching, subdirectory, parent, and unrelated client roots and every grant combination.

## Out of scope

This change does NOT include Session Scratch mutation (`rfs-60g1`); archive mutation (`rfs-trdn`); SQLite mutation (`rfs-c85i`); GitHub mutation or operation-ID deduplication (`rfs-by2z`); Vault mutation (`rfs-nb4s`); skill/rule mutation (`rfs-cdlp`); notebook projection editing (`rfs-xiwg`); arbitrary binary mutation (`rfs-6le8`); automatic parent-directory creation; block-star/register patch forms; cross-source or copy/delete cross-filesystem moves; power-loss durability; preservation of timestamps, ownership, xattrs, rich ACLs, flags, or alternate streams beyond platform replacement behavior; arbitrary mutating SQL; or source-native remote transaction semantics.
