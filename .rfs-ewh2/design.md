# Design: Typed self-describing namespace catalogs

## Route and inputs

- **Route:** Structural, from `.rfs-ewh2/route.md`. The change extends the public Path Reference and MCP Behavior Contract but has no unverified empirical premise.
- **Behavior source:** `.rfs-ewh2/spec.md`, approved 2026-08-22. Its complete behavior set is authoritative: read the mounted-source catalog; read declared Workspace Roots; reflect client root-set changes; preserve common bounded-read behavior; classify catalog Resources immutable; redirect unsupported search/glob; advertise discovery at initialization.
- **Edge decisions:** `.rfs-ewh2/spec.md#Decisions`. Canonical `rfs://` and `rfs://workspace` with `rfs://workspace/` accepted as an alias; compiled registry only; a header that chains to `rfs://workspace` and states the common selector grammar once, then one sorted line per source; active/degraded-with-public-reason metadata; canonical `rfs://workspace/<root>/` root spellings that parse as root-directory references and teach on read until rfs-hwlm; explicit empty/no-primary messages; common `ReadToolOutput`; syntax-valid examples; `unsupported_projection` discovery redirect; `permission_denied` mutation contract.
- **Empirical premises:** N/A — Structural route, and `route.md` records T1 `no`.
- **Evidence/probe input:** N/A — the route does not run `prove-it-prototype`.

## Removed invariants

Additive except for one deliberately relaxed precondition: `WorkspacePath` gains a root value (empty relative path) constructible only through `WorkspacePath::root()` and reachable only from the canonical `rfs://workspace/<root>/` (or slash-less) spelling, so the catalog's rendered root lines parse. Containment is unaffected because a Workspace Root is trivially contained; relative and `file://` spellings still cannot produce an empty path, and `WorkspacePath::new` keeps rejecting empty input. Otherwise the design adds two typed catalog addresses and one registry-derived read module and removes no guard, serialization point, uniqueness rule, ordering guarantee, or existing address interpretation.

## Placement

### Typed catalog identity

- **Owner:** `resourcefs-core/src/reference.rs`. It already owns `PathReference::parse`, `ResourceAddress`, canonical constructors, selector candidates, and every URI/path ambiguity. Add `CatalogAddress::{Sources, Workspace}` and `ResourceAddress::Catalog(CatalogAddress)`; parse `rfs://`, `rfs://workspace`, and the alias `rfs://workspace/` before generic workspace parsing (the alias must be checked ahead of the existing `rfs://workspace/` prefix branch at `reference.rs:588-591`, which today rejects it as missing a root). The alias's canonical rendering is `rfs://workspace`.
- **New seam:** no new seam. This extends the existing `PathReference` interface and its closed typed address sum.
- **Forbidden:** MCP string-prefix interception; treating catalogs as `WorkspaceAddress`; any alias beyond `rfs://workspace/` (and the slash-less root-directory form in the next section); accepting selectors on catalog references. `resource.rs::validate_canonical_identity` and every exhaustive `ResourceAddress` match must acknowledge the new typed variant.

### Root-directory references

- **Owner:** `resourcefs-core/src/reference.rs` for grammar; `FilesystemSource` for the read outcome. The workspace catalog renders each root as `rfs://workspace/<root>/`, so that spelling must parse: an empty remainder after `<root>/` (or a bare `<root>` with no slash) yields `WorkspaceAddress::Canonical { root, path: WorkspacePath::root() }`, and rendering a root path produces the trailing-slash form.
- **New seam:** `WorkspacePath::root()` and `WorkspacePath::is_root()`. The root value is never produced by `WorkspacePath::new` (which keeps rejecting empty input), by relative spellings, or by `file://` URIs, so existing callers keep their non-empty assumption unless they opt in; `open_workspace_entry` already handles the empty path (`filesystem.rs:1280-1302`) and gains a canonical reference for that entry instead of `None`.
- **Read outcome today:** directory reads are unimplemented for every directory (`read_address` rejects non-files at `filesystem.rs:2327-2331`). Reading a root-directory reference therefore returns `unsupported_projection` with a directory teaching message — `Resource '<ref>' is a directory; enumerate it with rfs_glob or read a file below it; bounded directory listings are tracked by rfs-hwlm` — never `invalid_reference`. rfs-hwlm replaces that message with the listing for the same reference.
- **Alternative — rejected:** implementing bounded directory-listing reads inside this change. That is a new projection for every directory, not a discovery concern; it is tracked as rfs-hwlm.
- **Forbidden:** rendering any root spelling the parser rejects; letting relative `""` or `.` denote a root; changing glob/search traversal semantics for the empty path.

### Adapter self-description and source catalog rendering

- **Owner:** a private `resourcefs-sources/src/catalog.rs` module composed by `CompiledSources` in `compiled.rs`. The sources crate is the only module that knows the compiled adapter inventory; core lacks that inventory and MCP must not acquire it.
- **New seam — chosen shape:** a crate-private `SourceCatalogMetadata` interface with `catalog_entries(&self) -> Result<Vec<SourceCatalogEntry>, ResourceError>`. `FilesystemSource` and `ArtifactSource` implement it in their owning modules. `CompiledSources::catalog_metadata()` is the one stack-allocated registry of `&dyn SourceCatalogMetadata`; each catalog read flattens the current descriptions, validates/sorts once, and passes them to the private `NamespaceCatalog` renderer. Adding an adapter requires registering the adapter in `CompiledSources`; its self-description then appears without editing catalog rendering. The filesystem adapter's entry uses scheme label `rfs://workspace` with grammar `rfs://workspace/<root>/<path>[:selector]` and the note that relative paths resolve only under the Primary Workspace Root; the artifact adapter's entry uses `artifact://` with grammar `artifact://<session>-<id>[:selector]`. Structural validation of the flattened entries (count, uniqueness, field shapes, example parsing) also runs once at `CompiledSources` construction so a misregistered build fails construction rather than every `rfs://` read; each read re-flattens (degraded state is live), re-validates cheaply, and sorts.
- **Alternative A — rejected:** extend core `SourceAdapter::read` with description methods. Prior designs `.rfs-vl0u/design.md` and `.rfs-r9m6/design.md` deliberately separated independently-varying discovery/probe capabilities; extending `SourceAdapter` would force composites and read-test fakes to invent metadata answers.
- **Alternative B — rejected:** central literal descriptor table in `catalog.rs`. It duplicates the compiled registry, permits routing a source without advertising it, and requires catalog-specific edits for every adapter.
- **Alternative C — rejected:** intercept `rfs://` in MCP `dispatch_read`. It creates a second routing convention, bypasses `ReadEngine` limits/recovery, and violates the dependency-direction architecture fence.
- **Forbidden:** per-source grammar/example strings in MCP or `CompiledSources`; dropping invalid metadata as if unmounted; running `SourceProbe` during a catalog read; an `Unmounted` state variant; caching rendered catalog text. Metadata fields are non-empty, single-line, at most 4,096 UTF-8 bytes; examples must parse; registry count is 1–256; duplicate scheme labels fail with `ambiguous_reference`.

### Workspace-root snapshot and rendering

- **Owner:** `FilesystemSource` owns authority; `NamespaceCatalog` owns presentation. Change private `WorkspaceView.roots` to `Arc<WorkspaceRootSet>` and add a crate-private `workspace_root_set()` that calls existing `active_view()` and returns an `Arc` clone. `NamespaceCatalog` sorts IDs and renders the approved text without seeing `FilesystemRoot`, backing paths, or `WorkspaceView`.
- **New seam:** the crate-private immutable `Arc<WorkspaceRootSet>` snapshot. It is narrower than exporting filesystem internals, copies no root strings, and releases the authority lock before rendering.
- **Alternative — rejected:** return separate root and primary values from separate lock acquisitions. A refresh can mix generations. Returning one immutable root set makes that state impossible.
- **Forbidden:** launch-view fallback while authority is Refreshing/Disabled; holding the authority lock during formatting; exposing backing URI, selector name, grant data, `FilesystemRoot`, or `WorkspaceView`; caching the workspace catalog.

### Catalog document layout

- **Owner:** `NamespaceCatalog` in `resourcefs-sources/src/catalog.rs`. The `rfs://` document is: a header that (1) names `rfs_read` of `rfs://workspace` as the next discovery step and (2) states the common selector grammar exactly once — `:N`, `:N-M`, `:N-`, comma-separated ranges, `:raw`, `:page:N` — followed by one ` — `-separated `scheme — grammar — example` line per entry, sorted by scheme label, with `[degraded: reason]` appended to degraded entries. The `rfs://workspace` document is: one `rfs://workspace/<root>/` line per root sorted by root ID with ` (primary)` on the primary, or the approved status lines.
- **New seam:** no new seam; the layout is a private rendering constant with literal tests (C3, C4, C14).
- **Forbidden:** per-scheme repetition of the selector grammar; header text that varies with registry contents beyond the fixed chain; any timestamp or counter.

### Common read contract and immutability

- **Owner:** `CompiledSources::read` routes `ResourceAddress::Catalog` into `NamespaceCatalog`, which returns ordinary `SourceResource::text`. `ReadEngine` and MCP `render::success` remain unchanged.
- **New seam:** no new seam. Catalogs cross the existing `SourceAdapter -> SourceResource -> ReadEngine -> ReadResource -> ReadToolOutput` interface.
- **Forbidden:** catalog-specific `ReadToolOutput` fields; direct artifact retention in catalog code; custom paging; mutable `SourceResource`; a catalog branch in MCP rendering. The existing source-neutral pipeline supplies content-derived Version Tags, `mutable: false`, limits, continuation, and recovery.

### Search/glob redirect

- **Owner:** `resourcefs-core/src/discovery.rs`, at request-target validation before adapter I/O. `SearchRequest::new` rejects a catalog `SearchTarget`; `GlobTarget::new` rejects the two exact catalog spellings. Both call one core error helper returning `unsupported_projection` and `catalog references are read-only discovery; use rfs_read <same-reference>`.
- **New seam:** no new seam; this deepens existing validated request constructors. Defensive `ResourceAddress::Catalog` arms in `CompiledSources::search` use the same helper but are unreachable through valid requests.
- **Alternative — rejected:** MCP `execute_search`/`execute_glob` checks. Dispatch refreshes roots before those helpers, violating the existing validation-before-I/O contract and duplicating source-neutral behavior at the protocol layer.
- **Forbidden:** catalog search indexing; catalog hierarchy/glob semantics; a new error category; performing client-root acquisition for an already-invalid catalog discovery request.

### MCP discovery guidance

- **Owner:** existing literal descriptions in `resourcefs-mcp/src/server.rs`: all three `#[tool]` descriptions and `get_info().with_instructions`.
- **New seam:** no new seam. Prepend the same sentence, `Start with rfs_read of rfs:// to discover mounted sources.`, to each existing description/instruction string.
- **Forbidden:** prompt exposure, new tools, schema changes, or guidance only in one channel.

## Claims

- **C1:** `rfs://`, `rfs://workspace`, and the alias `rfs://workspace/` parse as typed catalog addresses (the alias with canonical reference `rfs://workspace`), while every existing Workspace/Artifact spelling and every other rejected neighboring spelling retains its prior behavior.
- **C2:** The source catalog contains exactly 1–256 validated, unique entries returned by the compiled `SourceCatalogMetadata` registry, sorted by scheme label; malformed, duplicate, empty, or oversized metadata fails explicitly rather than disappearing.
- **C3:** Each mounted entry renders one scheme/grammar/example line; degraded entries append one bounded already-redacted reason, active entries do not, and unmounted schemes have no registry entry.
- **C4:** The workspace catalog renders exactly the immutable root snapshot sorted by ID, marks only its primary, emits the approved empty/no-primary status, and exposes no backing path or grants for every 0–256-root shape.
- **C5:** A workspace catalog read observes one authority generation: after a completed client-root replacement it shows only the replacement set, and a refresh race yields one complete snapshot or existing `source_unavailable`, never a mixed catalog.
- **C6:** Catalog reads use the unchanged common read/result interface: non-empty text and unchanged object-rooted `ReadToolOutput`, canonical identity, text content type, content-derived Version Tag, `mutable: false`, and boundedness metadata.
- **C7:** Lower caller limits and server limits compose by minimum for catalog content, and any omitted catalog bytes remain losslessly recoverable through the existing artifact continuation/recovery contract.
- **C8:** `rfs_search` and `rfs_glob` reject each exact catalog target before root/source I/O with `unsupported_projection` and a text redirect naming `rfs_read` plus the same target.
- **C9:** Initialization instructions and every visible `rfs_*` tool description begin with the `rfs_read`/`rfs://` discovery cue without changing tool names or schemas.
- **C10:** Catalog text and Version Tags are deterministic for one registry/root snapshot and change exactly when rendered state changes; no timestamp, counter, probe, or cache participates.
- **C11:** Catalog rendering remains behind typed `CompiledSources` routing in the sources crate, so direct source-composite reads satisfy the catalog contract without MCP participation.
- **C12:** Both catalog addresses are structurally identifiable and every returned catalog Resource is immutable regardless of grants; rfs-73dz can exhaustively map the typed catalog variant to `permission_denied` without string matching.
- **C13:** Every root line the workspace catalog renders parses: `rfs://workspace/<root>/` (and slash-less `rfs://workspace/<root>`) yields a canonical root-directory workspace address that renders back as `rfs://workspace/<root>/`, is unreachable from relative or `file://` spellings, and `rfs_read` of it returns `unsupported_projection` with the directory teaching message naming rfs-hwlm, never `invalid_reference`.
- **C14:** The `rfs://` header names `rfs_read` of `rfs://workspace` and states each common selector form exactly once before the per-scheme lines.

## Non-goals and future work

### Permanent non-goals

- Searching catalog text or globbing a synthetic catalog hierarchy. The documents are intentionally small and non-hierarchical; the teaching redirect is the complete contract.
- Selectors or projections for the two catalog references, and any alias beyond `rfs://workspace/` and the slash-less root-directory form. The accepted aliases exist only because callers will type them after reading the catalog; the grammar otherwise stays small.
- Backing filesystem paths, selector names, or mutation-grant summaries in workspace-root output. Canonical private identity is sufficient and avoids authority leakage.
- Catalog-specific structured-content arrays. The common `ReadToolOutput.content` representation is the approved schema.
- Per-read probes. Availability state is adapter-owned metadata; discovery reads must stay local, bounded, and side-effect free.
- A second catalog renderer, MCP dispatch branch, or new error category. Existing typed routing and `unsupported_projection` are sufficient.
