# Design: typed read-only GitHub Resources

## Route and inputs

- **Route:** Empirical, from `.rfs-45ww/route.md`: GitHub REST semantics were external premises; the change also crosses the public Path Reference/profile/source seams and carries network, pagination, cache, and rate-limit risk.
- **Behavior source:** `.rfs-45ww/spec.md`, re-approved 2026-08-25 after empirical evidence P5. It owns the complete given/when/then set: repository authority; typed issue/PR Aggregate and Field Resources; repository-scoped listing/search; bounded pagination and source continuations; conditional session cache; machine-signal error classification and bounded retry; valid absent fields; required/degraded lifecycle; and deterministic fake-upstream verification.
- **Empirical source:** `.rfs-45ww/evidence.md` plus `.rfs-45ww/probe_github_api.py`. P1–P6 are **PASS**. The independent oracle is official GitHub documentation/OpenAPI plus `gh api`/`jq`, which differs from the Python standard-library probe and the planned reqwest/serde implementation.
- **Empirical facts carried forward:** canonical issue/PR paths use repository-scoped `number`, not cross-endpoint `id`; issue comments, reviews, and inline comments have distinct endpoints and IDs; review fields include documented optional/null branches; unified diff media and optional file `patch` are real; Link targets are authoritative and may carry opaque cursors; ETag conditional reads return `304`; numeric page 2 matched the observed Link target; and status/header signals intentionally leave some `404`/secondary-`403` ambiguity.
- **Delivery increments from spec:** N/A — `spec.md` names no delivery increments; `budgeted-plan` owns slice and PR-increment decomposition after this design is approved.

## Removed invariants

The change is additive at the product surface but removes four implementation constraints that previously guaranteed safety:

1. **Only five `ResourceAddress` variants existed.** Exhaustive matching guaranteed no source family could bypass canonical-identity, read, discovery, or mutation routing. Adding `Issue`/`PullRequest` must keep every match exhaustive and refuse mutation explicitly. Covered by C1 and C16.
2. **`HttpRequest` carried only a URL.** That guaranteed a Source Adapter could not smuggle credential, cookie, host, or hop-by-hop headers into egress. Adding conditional/media/version headers must retain substrate-owned credential attachment and a denylist for authority-bearing headers. Covered by C4.
3. **`resourcefs-sources` had no JSON dependency.** The architecture fence over-approximated its real invariant—operator profile syntax/schema belongs to `resourcefs-mcp`. Allowing source-native GitHub wire decoding must not move profile DTOs or `schemars` into sources. Covered by C17.
4. **Path Session quota counted only artifacts, scratch, and snapshots.** Adding cached remote representations makes another retained-byte/object class possible; it must be admitted, replaced, and released under the same session ceiling. Covered by C10 and C20.

Still safe: core retains no network client, GitHub credential resolution remains in MCP profile mounting, every socket still crosses the existing resolver/redirect/address-policy implementation, and Aggregate/Field Resources remain ordinary immutable `SourceResource` values behind the existing engine.

## Placement

### Typed GitHub addresses

- **Owner:** `resourcefs-core::reference`. Syntax, canonical identity, numeric newtypes, and the exhaustive `ResourceAddress::{Issue, PullRequest}` sum belong beside every other Path Reference family. Core wins because every engine and adapter must consume the same parse-once value.
- **New seam:** No new external seam. Add validated `GithubRepositoryIdentity`, `IssueNumber`, `PullRequestNumber`, `ConversationCommentId`, `ReviewId`, `ReviewCommentId`, and `DiffFileIndex` newtypes plus exhaustive `IssueAddress`/`PullRequestAddress` sums. `PathReference::parse` constructs them once; sources only match variants.
- **Forbidden:** Raw owner/repository strings or numeric IDs below parsing/configuration; reparsing `requested()`; bool flags for issue-versus-PR or field kind; catch-all address arms; URL parsing of GitHub identities in MCP.

### Session-owned opaque cache

- **Owner:** `resourcefs-core::session`, because Path Session is the accepted owner of caches and shared quota.
- **Competing seam A (chosen):** `SessionCacheKey` newtype plus opaque `SessionCacheEntry { metadata: Arc<[u8]>, content: Arc<[u8]> }`; async `PathSession` get/put/remove methods own byte/object accounting, replacement deltas, isolation, and disconnect invalidation. GitHub stores ETag metadata and final rendered UTF-8 content without serializing a source DTO or copying on hits. High depth: quota and lifecycle disappear behind three source-neutral methods.
- **Competing seam B (rejected):** A `HashMap` inside `GithubSource` plus a core byte-reservation token. It keeps values typed but splits one cache mutation across two owners, requires async release from `Drop`, and can drift from quota state.
- **Competing seam C (rejected):** A GitHub-specific cache struct in core. It violates source-neutrality and would make every future cache add another core type.
- **Forbidden:** Uncharged cache bytes, sentinel empty validators, cross-session keys, disk persistence, stale-on-error returns, `Any` downcasts, or source-specific types in core.

### Bounded HTTP metadata

- **Owner:** `resourcefs-sources::http`, the workspace's sole egress module.
- **Competing seam A (chosen):** Deepen `HttpRequest` with validated non-secret request headers and deepen `BoundedHttpResponse` with typed optional ETag, Link, Retry-After, and rate-limit-remaining metadata. Constructors reject `Authorization`, `Proxy-Authorization`, `Cookie`, `Host`, transfer/framing headers, invalid names/values, and conflicting duplicates. `OriginCredential` remains the only credential attachment seam.
- **Competing seam B (rejected):** Expose reqwest `HeaderMap`/`Response` to adapters. It leaks the client implementation, permits secret-bearing headers, and makes bounded retention unenforceable.
- **Competing seam C (rejected):** Add GitHub-specific methods to `HttpSubstrate`. It creates a shallow source wrapper and prevents downstream MCP from reusing conditional/header behavior.
- **Forbidden:** A second client crate or policy layer; direct reqwest from `github.rs`; arbitrary retained response headers; credential values in `Debug`/errors; redirect or Link traversal outside existing origin/address checks.

### GitHub wire and Source Adapter

- **Owner:** new private `resourcefs-sources::github` module. Native API endpoints, typed wire DTOs, rendering, pagination, cache orchestration, retry, and status mapping are source behavior.
- **Competing seam A (chosen):** Private serde DTOs and `serde_json`/`serde_path_to_error` inside sources, converted immediately into validated domain values and rendered immutable Resources. Revise the architecture fence to allow serde/serde_json only for source-native wire formats while continuing to forbid `schemars`, `rmcp`, MCP profile DTOs, and public wire types.
- **Competing seam B (rejected):** A fourth `resourcefs-github` crate. One adapter would create a shallow crate/interface and move complexity rather than hide it.
- **Competing seam C (rejected):** Decode JSON in `resourcefs-mcp` and pass DTOs downward. That reverses dependency direction and couples Source behavior to protocol/profile code.
- **Competing seam D (rejected):** Manual JSON parsing. It duplicates a mature parser, mishandles nullable/unknown fields, and makes precise malformed-data errors harder.
- **Existing seams used:** `SourceAdapter::read`, `DiscoveryAdapter::search`, `SourceCatalogMetadata`, `SourceResource`, pattern matching, Read/Discovery engines, `OperationGuard`, `HttpSubstrate`, and `PathSession` cache.
- **Forbidden:** Public GitHub wire DTOs; string matching on GitHub error messages; constructing next Link URLs while Link is present; following same-origin Links outside the expected repository/endpoint family; fetching full item Aggregates during repository-collection search; mutable Resources.

### Profile and launch composition

- **Owner:** `resourcefs-mcp::profile` resolves the secret and constructs the bounded transport; `resourcefs-mcp::launch` carries a checked mount; `resourcefs-mcp::server` binds it to the newly created Path Session.
- **New seam:** `GithubSourceMount` in sources contains validated `GithubConfig` plus `Arc<HttpSubstrate>` and exposes one consuming `bind(PathSession) -> GithubSource`. `mount_github` uses the same `HttpSubstrate` implementation as HTTPS but a separate instance, preventing overlapping-source credential selection from becoming configuration-order dependent. `LaunchPlan` carries the mount until session creation.
- **Alternative rejected:** Pass `PathSession` through every `SourceAdapter::read` call. It broadens the deepest engine seam for one source even though only construction varies.
- **Forbidden:** Secret resolution in server/source read paths; normal-read connectivity probes; multiple GitHub mounts; silently ignoring uncompiled GitHub profile entries; merging GitHub and arbitrary HTTPS credentials by first-match ordering.

### Compiled dispatch and presentation

- **Owner:** `CompiledSources` owns registration/read/search/mutation dispatch and catalog entries; `resourcefs-mcp::server`/`render` keep generic result rendering and update only truthful tool descriptions.
- **New seam:** No new engine seam for read. `CompiledSources::new` receives `Option<GithubSource>` and exhaustively routes both address variants. `SearchSourceResult` gains an optional typed source continuation so network collection search can preserve the approved `:page:` reference without hiding it in matched text; DiscoveryEngine carries it to `SearchResult` while retaining artifact recovery for already-produced output.
- **Forbidden:** GitHub-specific MCP tools/result schemas; protocol-layer Aggregate rendering; treating GitHub paths as workspace glob patterns; mutation shims; aliases for old constructor signatures.

### Deterministic fake upstream

- **Owner:** `resourcefs-sources/tests/support` for source-neutral TLS/request fixtures and `github_adapter_contract.rs` for GitHub routes/oracles.
- **New seam:** Extend the existing TLS fixture to record bounded request method/path/safe headers and emit status/headers/body/trickle responses. A GitHub fixture maps exact REST routes to fixed JSON/diff pages and exposes request counts. Production code never sees the fixture interface.
- **Forbidden:** Live GitHub in permanent tests, mocks that bypass `HttpSubstrate`, assertions on helper call order, credential output, or fixtures that always succeed.

## Claims

- **C1:** Every accepted `issue://`/`pr://` spelling parses once into a validated exhaustive address variant and round-trips to one canonical reference; malformed/unsupported shapes fail deterministically.
- **C2:** Repository allowlist and source-state checks occur before request construction, case-insensitively for canonical ASCII identity, so an unallowlisted repository produces zero upstream requests.
- **C3:** Item paths use repository-scoped issue/PR `number`; comment/review paths use their collection's stable numeric `id`; cross-endpoint object `id` is never substituted.
- **C4:** GitHub sends only validated non-secret request headers through `HttpSubstrate`; origin credentials, redirects, DNS/address policy, TLS, body ceiling, timeout, and cancellation remain substrate-owned.
- **C5:** Every returned Link is followed verbatim only after both origin/address authorization and expected owner/repository/endpoint-family validation.
- **C6:** Private wire DTOs accept every documented nullable/optional branch and unknown extra field, but missing/invalid required identity returns `source_unavailable` with a bounded path-aware diagnostic.
- **C7:** Issue/PR Aggregate and Field renderings exactly follow the approved stable order, metadata set, explicit-absence rules, canonical child references, and content-derived Version Tags.
- **C8:** Conversation comments, reviews, inline review comments, unified diff, and indexed diff files remain distinct immutable projections; omitted `patch` produces explicit metadata rather than failure or empty patch fiction.
- **C9:** A logical collection fetches 100 objects per upstream page and at most 10 pages/1,000 objects, returns a typed source continuation for more, and returns no successful partial Aggregate after any page failure.
- **C10:** Conditional cache entries are isolated and charged to one Path Session; ETag `304` reuses final content, changed `200` replaces it atomically, missing ETag refetches, failure never serves stale content, and disconnect invalidates all entries.
- **C11:** Status mapping uses only numeric status and typed headers: all `404` collapses to `not_found`; signaled rate `403`/all `429` is `source_unavailable`; other `403`/`401` is `permission_denied`; `5xx`/network/malformed wire is `source_unavailable`; limits/cancellation retain their categories.
- **C12:** At most one eligible retry occurs, and first attempt, Retry-After wait, retry, pagination work, and cancellation share one configured logical deadline no greater than 30 seconds.
- **C13:** Required unavailable GitHub sources fail launch; optional ones mount visibly degraded; explicit check probes use the configured credential; ordinary reads perform no extra lifecycle probe.
- **C14:** Search applies the existing regex/PCRE2 and case rules to the exact rendered target Resource, not a second GitHub search API, and preserves source/artifact continuations.
- **C15:** Generic line/raw selectors, inline limits, artifact spill/recovery, non-empty text, and structured results remain Read/Discovery engine behavior for GitHub Resources.
- **C16:** Compiled dispatch/catalog advertise `issue` and `pr` only when mounted, route read/search exhaustively, reject mutation as `unsupported_mutation`, and leave existing families unchanged.
- **C17:** Source-native serde decoding stays private to `resourcefs-sources`; operator profile/schema ownership remains in MCP, `schemars` stays forbidden in sources, and core remains free of GitHub/HTTP/JSON implementation dependencies.
- **C18:** Profile conversion/mounting resolves exactly one GitHub credential without disclosure, validates one scheme owner, supports enterprise API base paths/private-network grants, and binds cache only after Path Session creation.
- **C19:** Deterministic direct-adapter tests cross the real typed parser, GitHub adapter, bounded HTTP substrate, and fake TLS upstream; no permanent test performs a live mutation or bypasses policy.
- **C20:** Network/retained work is bounded at every layer: 8 MiB per HTTP response, 100 objects per page, 10 pages per collection, 1,000 discovery results, and shared Path Session object/byte ceilings without avoidable response-body copies on cache hits.
- **C21:** Repository issue listing requests all states sorted by updated time, filters rows carrying `pull_request`; PR listing requests all states; ties use numeric number; empty collections succeed explicitly.

## Non-goals and future work

- **Intended future work — rfs-by2z:** GitHub Field mutation, comments/new, issue/PR Creation Targets, mutation grants, compare-before-write, and operation-ID behavior. rfs-45ww returns `unsupported_mutation` for every GitHub Resource.
- **Intended future work — rfs-ww6w:** MCP Resources/templates mirror the Path Reference space. rfs-45ww uses the existing canonical `rfs_read`/`rfs_search` tool seam and adds no GitHub-specific protocol surface.
- **Permanent non-goal for this change:** labels, assignees, milestones, reactions, requested reviewers, checks, and commit/file statistics in Aggregate output. They add unnamed response shapes/calls and are absent from the approved metadata contract.
- **Permanent non-goal for this change:** network-backed glob/completion and cross-repository scheme-root search. Repository collection reads/search are explicit and bounded; broad fan-out would violate the approved authority/scale shape.
- **Permanent non-goal for this change:** stale-on-error cache responses, disk-persisted GitHub cache, automatic retry beyond one attempt, error-message matching, live mutations in tests, a second HTTP client/policy layer, and a public GitHub wire schema.
- **Permanent non-goal for this change:** GraphQL. Native REST endpoints directly expose every approved projection and supply the proven HTTP metadata.
