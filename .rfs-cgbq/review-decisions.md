# Review decisions: rfs-cgbq

| finding-id | finding | reviewer | evidence-state | evidence | decision | fix | note |
|---|---|---|---|---|---|---|---|
| F1 | Parked root refreshes start their five-second deadline before request-associated acquisition can begin; split parking from timed acquisition. | ContainmentSecurityReview | Verified | `parked_root_refresh_does_not_expire_before_acquisition_starts` failed against the reviewed implementation after 60 seconds of paused time; `begin_client_root_refresh` armed its watchdog immediately. | Accept | Review-fix slice `serialize-bounded-root-acquisition`: keep the parked epoch non-expiring and stamp/arm the deadline only in `start_client_root_acquisition`. | This restores the requester-approved design in `.rfs-cgbq/design.md:250-256,302-308`; its focused and final checkpoints must pass. |
| F2 | Concurrent request handlers can overlap `roots/list` acquisitions and a second request can bypass an in-progress refresh; serialize complete acquisition loops while notifications replace one latest parked token. | ContainmentSecurityReview | Verified | Direct control-flow inspection showed `root_sync` released before `roots/list`, `Acquiring` returned early from another request, and `list_changed` replaced `Acquiring` with `Pending`; the compiled regression sends two tool calls around one held `roots/list` response and requires both to succeed with one acquisition. | Accept | Review-fix slice `serialize-bounded-root-acquisition`: separate the short-held pending-token mutex from a full acquisition mutex, consume only the latest token in a guarded loop, and re-check for superseding notifications before tools continue. | This restores `.rfs-cgbq/design.md:302-308` and bounds one connection to one live acquisition. |
| F3 | A timed-out rmcp `roots/list` permanently leaks its local responder entry; patch/upgrade rmcp or close the connection. | ContainmentSecurityReview | Refuted | rmcp 3.1.3 `RequestHandle::await_response` sends `notifications/cancelled` on its configured timeout (`service.rs:553-560`); the outbound cancellation `SendTaskResult` removes the matching `local_responder_pool` entry (`service.rs:1457-1464`). The reviewed outer `tokio::time::timeout` was wrong because it bypassed this path, but the SDK-supported timeout does unregister locally. | Reject | N/A — no dependency patch, upgrade, or forced connection close is warranted; F1/F2's slice still replaces the outer timeout with `PeerRequestOptions::with_timeout` and `RequestHandle::await_response` because the approved design already requires that API. | The bug claim omitted rmcp's outbound cancellation cleanup path. The replacement call path is verified by focused stdio timeout/recovery tests and final integration. |
| F4 | File-URI backslashes expose dot segments to later URL normalization, and absolute fast paths accept raw `?`/`#`; validate the downstream separator/delimiter grammar before normalization. | ContainmentSecurityReview | Verified | The expanded `golden_workspace_references` fence failed: `file:///workspace/dir\\..\\secret.txt` parsed and normalized to `file:///workspace/secret.txt` instead of failing; direct source reading confirmed absolute branches returned before delimiter rejection. | Accept | Review-fix slice `strict-normalization-boundaries`: validate file-URI backslashes as separators, reject raw ambiguous delimiters before address classification except the structural Windows verbatim prefix, and retain encoded delimiter support. | The expanded golden corpus is the permanent fence; its focused and final checkpoints must pass. |
| F5 | The golden corpus omitted exact Windows root-edge and malformed namespace spellings. | RootAuthorityReview | Verified | Before the fix, the corpus lacked trailing UNC/verbatim-UNC roots, three/four-leading-slash UNC forms, local device namespace, missing-share, and `/C:/file` rows; the new four-leading-slash row reproduced an erroneous successful parse. | Accept | Expand `workspace_references.json` with every named form and replace component-count validation with strict UNC-tail and drive-root validation. | `golden_workspace_references` now passes on the host, and the Windows-specific `/C:/file` row remains compiled into the cross-platform corpus for native Windows execution under rfs-58r1. |
| F6 | Invalid MCP client root display names were silently discarded instead of rejecting the root set fail-closed. | RootAuthorityReview | Verified | `build_client_workspace_view` used `Option::filter`; `invalid_client_display_name_fails_closed` initially returned `Applied` for `bad/name`. | Accept | Validate `WorkspaceRoot::selector_name` with Workspace Root ID grammar, pass client names through unchanged, map invalid client metadata to `source_unavailable`, and retain disabled authority. | Direct core and source tests cover the public invariant and fail-closed generation transition. |
| F7 | `refresh_client_roots` duplicated the `Unseen` and `Pending` token-consumption transition. | RootAuthorityReview | Verified | Both match arms set `RootSyncState::Idle` and returned a `RootRefresh`; duplication made the serialized transition easier to change inconsistently. | Accept | Extract `take_pending_root_refresh`, which performs one state transition and returns `None` for `Idle`. | No behavior change; the concurrent and lifecycle MCP fences own the refactored transition. |
| F8 | `matching_roots` returned `unsupported_projection` as soon as one configured root equaled the target, before counting an overlapping parent root. | RootAuthorityReview | Verified | `overlapping_absolute_inputs_are_ambiguous` reproduced `unsupported_projection` for the nested root directory where two configured roots matched. | Accept | Accumulate non-empty matches plus a root-directory match flag, classify ambiguity from the complete match count, and only then classify a sole root-directory target as unsupported. | All root matches are inspected before the error category is selected. |
| F9 | Absolute and `file://` inputs were compared lexically to handle-canonical configured roots, rejecting an existing caller spelling through a symlinked declared root. | RootAuthorityReview | Verified | `configured_root_symlink_accepts_declared_absolute_spelling` initially returned `permission_denied` for an existing file under the configured symlink spelling. | Accept | Canonicalize an existing absolute target for root mapping, then retain capability-relative open plus final-handle containment/ambiguity revalidation as the authority boundary. | Canonicalization maps identity only; it does not read content or replace final handle checks. |
| F10 | On POSIX, a parser-classified Windows absolute path remained a native relative `PathBuf`, so ambient canonicalization could map a drive/UNC-shaped filename under the process working directory. | FinalSecurityReview | Verified | With the active root set to the repository working directory, `rejects_non_native_windows_absolute_spelling_before_ambient_mapping` initially read `must not be read` from temporary `C:\\secret-*` and `\\\\server\\share\\secret-*` filenames. | Accept | Reject every `WorkspaceAddress::Absolute` whose `Path::is_absolute` is false on the running platform before ambient canonicalization; retain cross-platform syntax classification in core. | The source boundary now enforces the accepted “Windows forms resolve only on Windows” contract and the POSIX regression returns `invalid_reference` without reading the file. |
