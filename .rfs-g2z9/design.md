# Design: the bounded HTTP substrate and the `https://` Source Adapter

## Route and inputs

- **Route:** Empirical, from `.rfs-g2z9/route.md` — the transport's address-authorization hooks were unverified external behavior; the change also adds a public address family, a shared substrate seam, and network-scale risk.
- **Behavior source:** `.rfs-g2z9/spec.md`, signed 2026-08-23 (and re-signed the same day when the deferred client decision resolved). Its Decisions table is authoritative. Complete behavior set: read an allowlisted document in reader mode; read the original body with `:raw`; reject an over-ceiling document; search an allowlisted document; authorize every redirect hop and resolved address; require a distinct grant for private/special addresses; deny an unallowlisted reference without leaking; honor cancellation and the request timeout; fail startup for a required source and degrade an optional one; report connectivity through an explicit probe.
- **Empirical source:** `.rfs-g2z9/evidence.md` + `probe_http_substrate.py`, P1–P4 all **PASS**, every verdict reproduced across two full end-to-end runs. The four findings this design is built on:
  1. **Resolution is the enforcement point.** reqwest calls the resolver once per new connection and connects to exactly the `SocketAddr`s that call returned; a resolver returning `Err` opens no socket at all (0 accepts on both listeners). There is no "validate, then connect" gap to close — policy belongs *inside* the `Resolve` implementation.
  2. **`redirect::Policy::custom` vetoes before the request is sent** — the off-allowlist server's path log was empty, direct evidence the URL was never transmitted.
  3. **A byte ceiling bounds accepted/retained bytes, not bytes transferred** — a 1 MiB ceiling still saw ~3 MiB flushed by the peer. Every claim states the accept/retain bound.
  4. **Canonical output must never derive from a `Debug` rendering** — `{:?}` on a `StrTendril` embedded tendril's inline-vs-heap storage discriminator, which changes with string length.
- **Client decision (resolved, not re-litigated):** `reqwest` 0.13.2 via ungated public hooks — `ClientBuilder::dns_resolver`, `redirect::Policy::custom`, `bytes_stream()`.
- **Requester-fixed ceilings:** fetch 8 MiB, redirect depth 5, request timeout 30 s; each lowerable by the Server Profile, never raisable.

## Removed invariants

This change is **subtractive** beneath its additive surface: it removes the invariant *"ResourceFS performs no policy-bearing network egress; the read path touches only local state."* Walking the chain of facts that invariant silently guaranteed:

- **It guaranteed no SSRF surface.** Removing it means a caller-supplied reference can cause an outbound connection, so the resolved address becomes a security decision. → **C2**, **C3**, **C11**.
- **It guaranteed no untrusted remote bytes entered the bounded-read pipeline.** Removing it means hostile markup and oversized bodies reach the extractor and the ceilings. → **C8**, **C9**.
- **It guaranteed error text could not describe network topology.** Removing it means denial messages can leak resolved addresses or credential material. → **C12**.
- **It guaranteed reads were reproducible from local state.** Removing it means the same reference can yield different content and Version Tags across calls — accepted deliberately (spec: no caching, HTTPS is read-only, so no edit depends on a stable tag). *Still safe; no claim needed beyond C13's read-only classification.*
- **It guaranteed there were no TLS trust decisions.** Removing it means certificate verification enters the trust base, and it must stay bound to the hostname even though the connection is pinned to a validated address. → **C6**.

One further invariant is weakened by the substrate charter rather than by the transport itself:

- **`NetworkProbe` was the workspace's only egress, and being purely a reachability check, being unpoliced was tolerable.** Verified: `crates/resourcefs-sources/src/probe.rs:58` calls `TcpStream::connect((host, port))`, resolving through the system resolver with **no address policy**, and it is the only `TcpStream::connect` in the workspace. Once this change declares the substrate "the single point of network egress", that unpoliced path becomes an inconsistency with a real consequence: an origin configured `allow_private_network: false` whose host resolves to a private address still gets a startup probe connection to it. → **C15** closes this; it is not deferred.

A third invariant is narrowed, discovered by grounding this design in the parser rather than assuming it:

- **The global encoded-separator guard.** `validate_reference_input` calls `validate_percent_encoding` on the *entire* input before any family dispatch (`reference.rs:786-797`), rejecting `%2F` or `%5C` anywhere with `invalid_reference("Path Reference must not contain an encoded separator")`. That guard exists for **filesystem containment** — an encoded separator inside a workspace path could smuggle a traversal past segment validation. Applied globally it also rejects **legitimate HTTPS URLs**: `https://example.com/search?q=a%2Fb` encodes a literal slash correctly and is a listed production-reachable input shape. An HTTPS reference is not a filesystem path — its containment controls are `base_url` prefix scoping (C10) and address policy (C2/C3/C11), neither of which is affected by percent-encoding in the path or query. The guard is therefore **narrowed to the filesystem-backed families** (workspace, and `local://` scratch names) and no longer applied to `https://` references. This weakens a live security guard's blast radius, so it gets its own claim rather than a footnote. → **C19**.

**Still safe:** the existing bounded-read, selector, `artifact://` recovery, Path Session, and `OperationGuard` cancellation machinery is reused unchanged; HTTPS adds no mutation path, so per-Resource serialization and Version-Tag-before-commit rules are untouched.

## Placement

### `https://` address family
- **Owner:** `resourcefs-core/src/reference.rs`. Add `ResourceAddress::Https(HttpsAddress)` to the closed sum and parse `https://…` **before** the generic `input.contains("://")` rejection at `reference.rs:840` (which is what currently produces "unsupported Path Reference scheme"). `HttpsAddress` wraps a validated `url::Url` — core already depends on `url`, so this costs no new dependency.
- **New seam:** none — extends the existing closed `ResourceAddress` sum exactly as `Catalog` and `Local` did.
- **Forbidden:** accepting `http://` (plain) as this family; a catch-all `_ =>` arm in any exhaustive `ResourceAddress` match instead of a real `Https` arm; MCP-layer string interception of `https://`; storing the credential anywhere in the address.

### Source-neutral HTTP policy
- **Owner:** new `resourcefs-core/src/http_policy.rs`. Pure decision logic over `std::net::IpAddr` and `url::Url`, with **no network and no client dependency**: `AddressClass` classification (loopback / private / link-local / CGNAT / multicast / unspecified / IPv4-mapped-private / public), `AddressPolicy::authorize(IpAddr) -> Result<(), ResourceError>` parameterized by the origin's `allow_private_network`, `OriginAllowlist::authorize(&Url) -> Result<&AllowedOrigin, ResourceError>` implementing `base_url` prefix scoping, and the `HttpCeilings` triple (fetch bytes, redirect depth, timeout).
- **Why core wins:** the security decisions become unit-testable with no sockets and no client, and every consumer of the substrate (GitHub, downstream MCP) shares one policy vocabulary. Core keeps zero new dependencies: `url` is already present and `std::net` is free.
- **New seam:** none — a plain module of value types, no trait.
- **Forbidden:** any network call, any `reqwest` type, or any transport concern in this module; policy duplicated in a consumer instead of called; classification derived from string matching on the host rather than from the resolved `IpAddr`.

### The bounded HTTP substrate (transport)
- **Owner:** new `resourcefs-sources/src/http/mod.rs` — **the only module in the workspace that constructs an HTTP client.** It builds one `reqwest::Client` configured with a `PolicyResolver` (implementing `reqwest::dns::Resolve`, calling core's `AddressPolicy` and returning `Err` to deny), `redirect::Policy::custom` (calling core's `OriginAllowlist` per hop and `attempt.stop()` to veto), the request timeout, and bounded body reads via `bytes_stream()` that stop at the fetch ceiling.
- **New seam — chosen shape:** a concrete `HttpSubstrate` struct exposing `async fn fetch(&self, request: HttpRequest, guard: &OperationGuard) -> Result<BoundedHttpResponse, ResourceError>`, held as `Arc<HttpSubstrate>` by each consuming adapter. `HttpRequest`/`BoundedHttpResponse` are source-neutral (URL, method, headers, body bytes, content type, final URL) and name no HTTPS-source type.
  - **Alternative A — rejected:** a `trait HttpTransport` in core with a `ReqwestTransport` impl in sources. It would allow a fake transport in core tests, but the security-critical logic lives *inside* the resolver, so a fake transport would test nothing about the actual control — and it adds a trait with exactly one production implementation, the shape this repository has previously flagged as speculative generality.
  - **Alternative B — rejected:** expose `reqwest::Client` to consumers directly. It defeats the single-egress fence outright: any consumer could build its own request bypassing the resolver and redirect policy.
- **Forbidden:** a second `reqwest::Client` anywhere; exposing the client, its builder, or `reqwest` types across the module boundary; following a redirect without consulting `OriginAllowlist`; resolving a host without consulting `AddressPolicy`; buffering a body before the ceiling check; deriving canonical output from a `Debug` rendering.

### Reader-mode extraction
- **Owner:** new `resourcefs-sources/src/http/extract.rs`. An in-house bounded HTML→Markdown pass over the `html5ever` tokenizer: drop `script`/`style`/`svg`, keep the defined tag subset (headings, paragraphs, lists, links, code, tables), normalize whitespace. Placed in sources beside `pattern.rs`, matching the established rule that parsing engines live in the sources crate, never in core.
- **New seam:** none — a pure function `extract(html: &str) -> String` behind the substrate.
- **Forbidden:** running over a truncated document (the ceiling check precedes extraction); `{:?}` / `Debug` rendering anywhere on the path that feeds a Version Tag; boilerplate or navigation heuristics (spec Out of scope); any output that varies with allocator state, iteration order, or string storage layout.

### The HTTPS Source Adapter
- **Owner:** new `resourcefs-sources/src/https.rs` — `HttpsSource` implementing `SourceAdapter` (read), `DiscoveryAdapter` (search), and `SourceCatalogMetadata`, mirroring the shape of `local.rs` and `artifact.rs`. It holds `Arc<HttpSubstrate>` plus the per-origin configuration derived from `HttpsSourceProfile`.
- **New seam:** none — fills existing seams. **No `MutationAdapter`:** HTTPS is read-only, so `CompiledSources` routes every `Https` mutation to `unsupported_mutation`.
- **Forbidden:** constructing an HTTP client (only the substrate may); re-implementing allowlist or address policy; caching a response; reporting `mutable: true`.

### Probe egress, unified
- **Owner:** `resourcefs-sources/src/probe.rs`. `NetworkProbe` must route its reachability check through the same address policy rather than calling `TcpStream::connect` on an unvalidated resolution, so a `allow_private_network: false` origin cannot be probed against a private address.
- **New seam:** none — `NetworkProbe` gains the policy dependency it currently lacks.
- **Forbidden:** any egress in the workspace that does not pass `AddressPolicy`; a second resolver path.

### Registration, capability fence, and dependency vetting
- **Owner:** `resourcefs-sources/src/compiled.rs` (register `HttpsSource`; `Https` arms for read/search/catalog; mutation → `unsupported_mutation`); `crates/resourcefs-mcp/tests/architecture_contract.rs` (extend the fence); `deny.toml` (vet the new transitive tree).
- **Fence mechanism (mirrors the existing `pcre2_sys` precedent at `architecture_contract.rs:213-235`):** `files_containing_token` scans every workspace `.rs` file (skipping `target/` and hidden directories) for the client identifier assembled at runtime — so the fence's own source does not self-match — and asserts the offender list equals exactly `["crates/resourcefs-sources/src/http/mod.rs"]`. A second assertion adds `reqwest` and `html5ever` to core's and mcp's forbidden dependency sets, alongside the existing `regex`/`pcre2-sys`/`cap-std` entries. A third asserts `TcpStream::connect` appears only in the policy-routed probe module.
- **Forbidden:** widening the offender list to silence the fence; adding the client to `resourcefs-core` or `resourcefs-mcp`.

## Claims

- **C1:** `https://<url>` parses to `ResourceAddress::Https` exactly for well-formed HTTPS URLs; `http://` and every existing address family retain their current parse result unchanged.
- **C2:** Address authorization lives inside the `Resolve` implementation: when policy denies a resolved address, **no socket is opened to it**.
- **C3:** A connection is established only to an address that policy authorized in that same resolution — a later resolution returning a different address never produces a connection to it.
- **C4:** Every redirect hop is authorized against the origin allowlist **before** it is requested; an off-allowlist hop is never transmitted.
- **C5:** A redirect chain deeper than the configured depth returns `limit_exceeded` and stops.
- **C6:** Over TLS, address authorization applies identically to the plain-HTTP path, **and** certificate verification remains bound to the requested hostname rather than to the pinned address.
- **C7:** A pooled connection is reused only to an address already authorized for that origin; pooling never yields a connection to an address policy did not authorize.
- **C8:** A body exceeding the fetch ceiling returns `limit_exceeded` with **no extraction performed**; a body at exactly the ceiling succeeds. The ceiling bounds bytes ResourceFS accepts and retains, not bytes the peer transmits.
- **C9:** Reader-mode extraction is byte-deterministic for identical input across runs and separate processes, and no canonical output derives from a `Debug` rendering.
- **C10:** Only URLs prefixed by a declared origin's `base_url` are reachable; a URL on an allowlisted host but outside its prefix is denied.
- **C11:** An origin with `allow_private_network: false` denies loopback, private, link-local, CGNAT, multicast, unspecified, and IPv4-mapped-private addresses; the same origin with the grant true permits them.
- **C12:** No resolved IP address appears in any tool result, error message, log line, or probe report, across success and every failure mode. *(Revision 2: narrowed to addresses. The credential half moved to C20 — see the Credentials input-shape row. `AddressPolicy::authorize` already names only the address class, never the address; C12 proves that rather than assuming it.)*
- **C20:** A configured origin's credential is transmitted on its requests, and the credential value appears in no tool result, error message, log line, probe report, or CLI diagnostic across success and every failure mode. *(Revision 2, added: requires request-header support on `HttpRequest`, an accessor on `CredentialHeader`, and `configured_sources` wiring — none of which exist today, which is why the leak half could not be fenced without it. Its slice must land the transmission before the leak-freedom scan can be non-vacuous.)*
- **C21:** An HTTPS read issued through the read engine honors cancellation — a cancelled read abandons its connection promptly rather than running to the request timeout, and returns `cancelled`. *(Revision 3, added: Slice 8 found `SourceAdapter::read` takes no `OperationGuard`, so `HttpsSource::read` constructs an always-active one. The substrate honors cancellation — C16 fences it — and `DiscoveryAdapter::search` does receive a guard, so the gap is confined to the read path: an `rfs_read` of an `https://` reference cannot be interrupted before the 30-second timeout. Closing it widens a core trait, so it lands with C20's slice, which already touches this seam for the `configured_sources` wiring. Fence per this stage's Named-mutation criteria: the mutation removes the guard from the read path and the fence must go red because the cancelled read runs to timeout — with a positive control proving an uncancelled read of the same fixture completes, so the assertion is not satisfied by the request simply failing.)*
- **C13:** HTTPS reads and searches use the common bounded-read/discovery contracts with no HTTPS-specific result fields, report `mutable: false`, and every `rfs_write`/`rfs_edit` against an `https://` reference returns `unsupported_mutation`.
- **C14:** A `required: true` HTTPS source whose probe fails prevents startup with a non-zero exit; a `required: false` source becomes visibly Degraded, the server starts, and only that source's references fail with `source_unavailable`.
- **C15:** The substrate is the single point of network egress: the HTTP client identifier appears in exactly one workspace module, and the probe's reachability check passes through the same `AddressPolicy` rather than connecting to an unvalidated resolution.
- **C16:** A cancelled read returns `cancelled` and a timed-out read returns `source_unavailable`; both abandon the connection and publish no Path Session state for the abandoned call.
- **C17:** `https://` self-lists in the `rfs://` source catalog with a grammar line and a valid example once mounted.
- **C18:** The substrate's request/response interface is source-neutral — it names no HTTPS-source type, so `rfs-45ww`/`rfs-by2z` and `rfs-azd3` can consume it without a second client or policy layer.
- **C19:** The encoded-separator guard still rejects `%2F`/`%5C` in every filesystem-backed reference (workspace and `local://`), while an `https://` reference carrying a percent-encoded separator in its path or query parses and is fetched with that encoding preserved byte-for-byte.

## Non-goals and future work

### Permanent non-goals (rationale recorded; no tracker issue)
- **HTTPS mutation** — the source is read-only; mutation of remote objects belongs to GitHub's native API path (spec Out of scope).
- **Plain `http://` origins** — TLS is required; admitting cleartext would put credentials and content on the wire.
- **JavaScript execution / headless rendering** — out of the bounded, deterministic extraction model.
- **Boilerplate/navigation stripping heuristics** — the requester chose a defined tag-subset pass precisely so output is deterministic; a heuristic extractor would churn Version Tags on upgrade.
- **Response caching** — requester decision: always current, nothing to invalidate, no competition for the session budget.
- **Cookie jars, session affinity, proxy configuration** — spec Out of scope; each would add unaudited state or a second egress path.

### Intended future work (verified tracker IDs)
- **rfs-45ww** / **rfs-by2z** — GitHub over native HTTP APIs consumes this substrate; C18 exists so it needs no second client or policy layer.
- **rfs-azd3** — downstream MCP over allowlisted Streamable HTTP likewise consumes it.
- **rfs-ww6w** — the MCP Resources mirror will expose `https://` references once mounted; no work added here.
