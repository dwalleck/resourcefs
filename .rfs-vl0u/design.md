# Design: Bounded workspace and artifact discovery

## Route and inputs

- Route: **Empirical**, from `.rfs-vl0u/route.md`. T1–T3 fire: external matcher/traversal behavior was unverified, the change crosses public crate interfaces, and recursive discovery carries latency, memory, cancellation, and data-volume risk.
- Behavior source: approved `.rfs-vl0u/spec.md`, including its complete Given/When/Then set, edge decisions, hard limits, partial diagnostics, Artifact continuation, and requester re-approval dated 2026-08-20.
- Empirical source: `.rfs-vl0u/evidence.md` plus `probe_pcre2.py`, `probe_ignore.py`, and `probe_globset.py`. P1–P4 are PASS; P5–P6 are classified N/A.
- P1: Rust-regex-first fallback, Unicode caseless search, direct PCRE2 match/depth limits, and typed `-47`/`-53` exhaustion are available. High-level `pcre2` is insufficient because it hides the required match context; PCRE2 JIT is forbidden because it does not enforce depth limits.
- P2: `ignore::WalkBuilder::follow_links(true)` follows an escaping ambient symlink. It cannot participate in Workspace authority.
- P3: capability-read `.gitignore` content can be compiled as one low-level `GitignoreBuilder` per containing directory and stacked parent-before-child without consulting ambient Git configuration.
- P4: globset matches the approved path language only when every glob explicitly enables literal separators and backslash escaping; its case folding is ASCII-only.
- Delivery increments from the behavior source: N/A — `spec.md` defines behavior rather than implementation increments; `plan.md` owns slice and review-increment decomposition.

## Removed-invariant sweep

The change is additive at the Source Adapter level because the existing `SourceAdapter::read` interface remains intact and a separate discovery seam is added. It is subtractive in MCP dispatch: replacing the current `request.name == "rfs_read"` guard removes the guarantee that one argument shape is the only production-reachable tool input. The replacement must preserve three facts: unknown tool names never reach source I/O; each known name is deserialized against only its own deny-unknown schema before root refresh; and each call owns one cancellation `OperationGuard`. C11 and C16 carry these invariants with raw JSON-RPC mutation fences.

## Placement

### Source-neutral discovery contract and bounding

- **Owner**: `resourcefs-core`, in a new `discovery` module. It owns `SearchTarget`, `GlobTarget`, request/options/limit types, stable record/diagnostic/result types, the `DiscoveryEngine`, deterministic sorting/deduplication, canonical recovery text, lower-only pagination, Path Session spill, and `InvalidPattern`/`Cancelled` error categories. These are Behavior Contract semantics, not filesystem or MCP details.
- **New seam alternatives**:
  1. Extend `SourceAdapter` with `search` and `glob`. Small surface, but it makes discovery mandatory for every read adapter and couples an already-stable read interface to a capability that not every source has.
  2. Add a separate two-method `DiscoveryAdapter` implemented by `CompiledSources`, `FilesystemSource`, and `ArtifactSource`. This preserves the read interface, expresses a real capability with two current adapters, and lets the adapters tracked under I14 implement discovery independently. **Chosen.**
  3. Add a generic async candidate stream and make core perform all traversal/matching. Rejected: traversal authority, ignore stacks, projections, and partial I/O errors leak through a shallow interface whose callers must understand source internals.
- **Forbidden**: core may not depend on rmcp, cap-std, regex, pcre2-sys, globset, or ignore; it may not reopen backing paths or interpret source-specific directory state. Source adapters may not implement pagination, Recovery Artifact publication, or MCP rendering.

### Pattern compilation and source traversal

- **Owner**: `resourcefs-sources`, behind a private `pattern` module and adapter-local traversal implementations. A small safe `SearchMatcher` interface hides Rust regex and all unsafe PCRE2 ownership; it is constructed and used inside one blocking worker. Filesystem traversal stays in `filesystem`; Artifact content/catalog operations stay in `artifact`; `compiled` dispatches by target family.
- **New seam alternatives**:
  1. Expose a public cross-crate matcher from core. Rejected: it would place external matching dependencies and unsafe FFI in the source-neutral module and enlarge the public interface for one internal variation.
  2. Keep one private matcher shared by the two compiled adapters. **Chosen:** all current and intended adapters live in `resourcefs-sources`, so one private module gives locality without a hypothetical public seam.
- **Forbidden**: no `ignore::WalkBuilder`; no ambient recursive walk; no JIT; no high-level `pcre2` wrapper; no string matching on error messages. `pcre2-sys` unsafe calls appear only in `pattern`; each allocation has RAII cleanup; matcher exhaustion is identified by typed constants. Filesystem content is read incrementally through capability handles, not buffered wholesale before matching.

### Workspace filtering and containment

- **Owner**: `FilesystemSource`. It snapshots the active view/generation, traverses `cap_std::fs::Dir` entries, opens links through the capability, obtains final handle paths using the existing platform functions, rejects outside targets, deduplicates final canonical identities, and revalidates authority before delivery. It reads `.gitignore` through the capability and feeds lines to a per-directory low-level matcher stack.
- **New seam**: N/A — the existing filesystem authority implementation already owns root selection, handles, final-path verification, and generation validation; discovery deepens that module.
- **Forbidden**: lexical prefix checks, ambient canonicalize-then-reopen, global Git configuration, `.ignore`, `.git/info/exclude`, and suppression of I/O errors without diagnostics.

### Path Session Artifact catalog

- **Owner**: `PathSession` in `resourcefs-core::session`. Add one public snapshot method returning current-session `ArtifactAddress` values in object-ID order after checking session liveness. `ArtifactSource` consumes it; storage directories remain an implementation detail.
- **New seam**: N/A — this is a new operation on the existing Path Session interface, not a second storage interface.
- **Forbidden**: scanning the disk store, accepting caller-supplied session tokens as catalog authority, including artifacts retained after the snapshot, or exposing another session.

### MCP schemas, dispatch, and rendering

- **Owner**: `resourcefs-mcp::server` for deny-unknown input schemas, per-tool pre-deserialization, cancellation racing, root refresh, and tool descriptions; `resourcefs-mcp::render` for object-rooted structured mapping plus complete TextContent.
- **New seam**: N/A — both tools slot behind the existing rmcp tool router and renderer interface.
- **Forbidden**: MCP code may not compile patterns, traverse sources, sort records, publish artifacts, reinterpret error categories, or materialize a second recovery document.

## Claims

- **C1**: The pinned matcher libraries can express the approved Rust-first fallback, Unicode search case folding, bounded non-JIT PCRE2 work, and glob language.
- **C2**: Core discovery request types enforce the 65,536-byte search-pattern ceiling and every lower-only limit before invoking a Source Adapter.
- **C3**: One private safe matcher selects Rust regex whenever it compiles, uses PCRE2 only after Rust rejection, and returns typed invalid-pattern or work-limit errors without unbounded backtracking.
- **C4**: Filesystem discovery never returns an outside byte or duplicate final identity while following contained links and observing each entry once.
- **C5**: Recursive filtering honors only contained root/nested `.gitignore` files and the approved hidden rules, while exact search targets bypass descendant filters.
- **C6**: Search emits each matching line once, groups and sorts by canonical Resource and line, and reports non-fatal descendant failures deterministically.
- **C7**: Glob implements the approved component syntax, ASCII case mode, entry kinds, slash rendering, ordering, and target grammar on every supported platform.
- **C8**: Artifact search and glob observe only immutable Resources from the active Path Session, and a recovery spill cannot enumerate itself.
- **C9**: Skip, all lower-only limits, text bounds, 1,000-record pages, 64 MiB recovery, continuation, and quota failure are lossless and deterministic.
- **C10**: The core engine checks operation/session liveness around adapter execution and immediately before retention, so cancelled or disconnected operations cannot publish a late Artifact.
- **C11**: The compiled MCP process lists and dispatches all three read/discovery tools and emits equivalent complete text and object-rooted structured results/errors.
- **C12**: Dependency direction and module ownership remain mechanical: rmcp stays in mcp; cap-std/regex/pcre2-sys/globset/ignore stay in sources; core owns only source-neutral contracts and recovery.
- **C13**: A 100,000-Resource/10,000-match operation remains bounded by the complete 64 MiB document budget and returns the exact 100-record initial page plus full recovery.
- **C14**: Filesystem root refresh and concurrent entry changes preserve per-entry consistency, reject removed authority, and never relabel partial observation as a whole-tree snapshot.
- **C15**: Path Session Artifact catalog snapshots are liveness-checked, object-ID ordered, current-session-only, and stable against artifacts retained after the snapshot.
- **C16**: MCP discovery schemas apply repository defaults, reject null/wrong/unknown fields per tool, and complete validation before root refresh or source I/O.
- **C17**: MCP cancellation returns a `cancelled` tool error within the controlled 250 ms budget, leaves the session usable, and exposes no late Artifact.
- **C18**: MCP client-root changes refresh discovery authority and prevent an in-flight removed-root result from becoming observable success.

## Non-goals and future work

### Permanent non-goals

- Multi-target/semicolon discovery, occurrence columns/context/replacement, shell extglob, ambient/global ignore configuration, indexing/watchers/background scans, mutable or cross-session Artifact discovery, and MCP Resource listing are excluded by the approved Behavior Contract. Adding them here would enlarge or duplicate the five-tool interface.
- Whole-tree snapshot consistency is excluded: Workspace discovery promises per-entry consistency so active editors/builds do not force a complete copy or lock.
- `ignore::WalkBuilder` and PCRE2 JIT are forbidden implementation choices because empirical evidence falsified their required containment/depth-limit properties.

### Intended work with verified tracker coverage

- rfs-60g1: Session Scratch discovery.
- rfs-trdn: archive search/glob.
- rfs-xiwg and rfs-9o5v: notebook and converted-document search.
- rfs-c85i, rfs-g2z9, rfs-nb4s, rfs-uo2w, rfs-cdlp, rfs-45ww, rfs-vl7z, and rfs-btji: database, HTTPS, Vault, Memory, Skill/Rule, GitHub, SSH, and Agent Export adapters consuming this seam.
- rfs-r9m6: strict profile fields that lower discovery limits.
- rfs-ww6w: separate bounded MCP Resource listing.
- rfs-5os7: real Kiro and release conformance proof for search/recovery/cancellation.
